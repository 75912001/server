# 服务器扩容设计

本文定义 server 项目的扩容语义、服务职责、实现约束和验收方式。扩容只接新流量, 不迁移已有 TCP 连接或 online actor。

## 设计目标

- 支持 login、gateway、online、cache 四类服务按实例横向扩容。
- 新增实例通过 etcd 加入同一 `projectName/groupID/name` 命名空间。
- `serverID`、监听端口和 `externalAddr` 必须在同一服务分组内唯一。
- gateway 和 online 使用动态 `availableLoad` 表示剩余承载能力。
- login 和 cache 不新增动态容量计数。
- 不新增 `connectTicket` 重签、多 gateway 票据或在线迁移协议。

## 扩容语义

### 不迁移已有在线账号

gateway 持有客户端 TCP 连接和本地 `Account` actor, online 持有账号业务 actor。扩容新增实例只影响后续选择:

- 新 login 实例只接外部 LB/网关分发过来的新 HTTP 请求。
- 新 gateway 实例只接 login 后续签发到该 gateway 的新 `connectTicket`。
- 新 online 实例只接 gateway 后续 `OnlineBindAccount` 的新绑定。
- 新 cache 实例只接后续 RingHash 路由到它的 Redis 访问请求。

已有 TCP 连接不从旧 gateway 迁移到新 gateway, 已有 online actor 不从旧 online 迁移到新 online。

### 服务发现和上线准入

xlib server 启动顺序是先启动 gRPC/TCP/HTTP 等网络监听, 再写入 etcd server key。因此本设计将“网络监听成功”作为实例进入发现的准入条件。

新增实例写入 etcd 后, 其他服务通过 add/update/del 回调更新本地服务列表。依赖发现和 stream 建立可能晚于 etcd 注册, 因此:

- gateway 选择 online 时必须确认该 online 的 `OnlineStreamTunnel` 已建立。
- cache resolver 允许新增节点后 RingHash 即时重分布。
- login 发现 gateway 后可立即签发到该 gateway 的 `connectTicket`。

### `availableLoad` 模型

`availableLoad` 表示剩余可承载资源, 通过 xlib 现有 30 秒周期写入 etcd。本轮不新增事件触发上报。

- gateway 容量单位: TCP 连接数。
- online 容量单位: 已绑定Account actor 数。
- login/cache 保持配置容量和健康含义, 当前内部调度不依赖它们的动态容量。

因为只依赖 30 秒周期上报, 全局可见容量最多存在一个上报周期的滞后。调用方仍保留本地预扣减, 用于减少短时间集中分配。

## 服务职责

### login

login 是 HTTP 登录入口。扩容后的请求入口由外部 LB、网关或 Ingress 负责, server 内部不通过 etcd 给客户端发现 login。

login 新增实例需要:

- 使用唯一 `serverID`。
- 使用唯一 HTTP 监听端口。
- 连接同一 etcd 和 cache/gateway 服务发现命名空间。
- 与 gateway 使用一致的 `ticketSecret`。

login 选择 gateway 时仍按本地发现到的 gateway `availableLoad` 最大优先, 选中后本地扣减 1。若目标 gateway 后续拒绝登录, 客户端重新申请登录凭证。

### gateway

gateway 是客户端 TCP 接入和 cache accountSession owner。扩容后:

- TCP `OnConnect` 尝试预留 1 个本地容量。
- 容量为 0 时不超卖, 后续验证请求快速返回不可用并断开。
- `OnDisconnect` 和所有清理路径必须归还已预留容量。
- 同一连接只能归还一次容量。
- 选择 online 时跳过 `availableLoad=0`、gRPC 不可用或 stream 未就绪的 online。

gateway 容量按 TCP 连接数计数, 包含未完成登录验证的连接。这样可以限制未认证连接占用接入层资源。

### online

online 是账号业务 actor owner。扩容后:

- 首次绑定某个 aid 的 user actor 时预留 1 个本地容量。
- `OnlineBindAccount` 容量为 0 时返回 gRPC `Unavailable`。
- 绑定失败必须归还预留容量。
- 重复绑定已存在的 user actor 不重复扣减容量。
- `OnlineUnbindAccount` 只有在 `gatewayKey + accountSession` 匹配并删除 actor 时才归还容量。
- 不匹配解绑不归还容量, 避免旧请求影响新 actor。

### cache

cache 是无状态 Redis 访问层。扩容新增 cache 实例后, xlib resolver 和 RingHash 会把部分后续请求路由到新实例。

cache 不保存账号在线状态, 底层 Redis Cluster 是共享数据源。因此 RingHash 即时重分布不需要迁移 Redis 数据。需要关注的是新增实例的 Redis 配置必须与已有 cache 一致。

## 失败处理

- `serverID`、端口或 `externalAddr` 冲突: 启动前校验发现后不启动新实例。
- gateway 容量耗尽: 新连接不占用业务容量, 验证请求返回不可用并断开。
- online 容量耗尽: `OnlineBindAccount` 返回 `Unavailable`, gateway 回滚 cache accountSession。
- online stream 未就绪: gateway 不选择该 online。
- 目标 gateway 拒绝已签发 `connectTicket`: 本次登录失败, 客户端重新申请 accountVerifyToken 并重新登录。
- cache 新增实例后请求重分布: 依赖 Redis/Lua/CAS 保证数据正确性。

## 部署约束

新增实例配置继续沿用显式 yaml 模式, 例如:

- `deploy/gateway/gateway.3.yaml`
- `deploy/online/online.3.yaml`
- `deploy/cache/cache.3.yaml`
- `deploy/login/login.3.yaml`

每个新增配置必须检查:

- `base.serverID` 未被同服务同 group 使用。
- `grpc.listenAddr`、`grpc.externalAddr` 唯一。
- gateway 的 TCP `net.listenAddr`、`net.externalAddr` 唯一。
- login 的 `custom.httpAddr` 和外部 LB 端口映射一致。
- etcd endpoints、`projectName`、`groupID`、服务名与目标集群一致。
- cache 的 Redis Cluster 配置与现有 cache 一致。

## 验收场景

### 单元测试

- gateway 容量预留和归还。
- gateway 重复清理不重复归还容量。
- gateway `OnlineMgr` 跳过 stream 未就绪或 `availableLoad=0` 的 online。
- online 新 actor 绑定扣减容量。
- online 绑定失败归还容量。
- online 重复绑定同一 actor 不重复扣减容量。
- online 匹配解绑归还容量, 不匹配解绑不归还容量。

### 手工验证

1. 新增 `.3.yaml` 配置并启动 gateway、online、cache、login 新实例。
2. 查看日志确认新实例网络监听成功并写入 etcd。
3. 查看旧实例日志确认收到 etcd add/update 事件。
4. 保持已有在线账号连接, 确认不会被迁移或踢下线。
5. 发起新登录, 确认 login 能选择新增 gateway。
6. 批量新登录, 确认 gateway 能选择新增 online。
7. 新增 cache 后验证 accountVerifyToken、AccountRecord 和 cache accountSession CAS 仍正确。
8. 将 gateway 或 online 容量设置为 0, 确认新请求快速失败且客户端可重新申请登录凭证恢复。

## 后续改进

- 如果需要更快放量, 可在容量变化时增加合并上报, 30 秒周期保留兜底。
- 如果需要无损缩容, 需要另行设计摘流、拒绝新登录、等待旧连接自然下线和强制踢下线策略。
- 如果需要登录失败后不重新外部认证, 需要新增 `connectTicket` 重签或多候选 gateway 票据设计。
