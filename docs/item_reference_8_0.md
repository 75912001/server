# 石器时代 8.0 道具资源映射参考

## 结果概览

本参考资料将道具 BMP 文件名解析为资源帧号, 经 ADRN 映射为 `itemset6.txt` 的
`imagenumber`, 再关联内部道具 ID 和完整配置字段.

以下数量是早期完整资源扫描与 CSV 展开结果, 不是当前工作簿“道具总表”的行数:

- 扫描 BMP 资源: 2782 个.
- 成功关联道具记录的资源帧: 1957 个.
- 当前 `itemset6.txt` 无对应记录的资源帧: 825 个.
- 展开一对多关系后的道具详情: 15054 条.
- `itemset6.txt` 有效记录: 15164 条, 每条均为 94 个原始字段.

当前仓库保留的文件:

- `item_reference_8_0.xlsx`: 带筛选、冻结表头、图片、分类说明和逐行修正记录的 Excel 工作簿.
- `item_reference_8_0.md`: 数据来源、映射规则、分类口径和维护约束.

当前工作簿包含 10327 条“道具总表”数据记录, 其中 9587 条匹配到 `itemset6.txt`,
740 条只有资源记录而没有内部道具 ID. 第 2 行是字段说明, 不计入数据记录.

2026-08-11 分类审计共修正 1445 条记录, 新增“分类说明”和“分类修正”标签.
历史 CSV 文件和生成器当前不在仓库中. 若以后重新导出 CSV, 应使用 UTF-8 with BOM,
以便 Excel 直接打开且不出现中文乱码.

- ADRN: `D:\csa_8.0\data\adrn_136.bin`.

  `D:\石器资源\石器时代8.5的服务端源码LINUX下开发\85\gmsv\include\item.h`.
- 字段和运行逻辑参考: 8.5 原版服务端 `gmsv/item/item.c`, `gmsv/char/char_item.c`
  和 `gmsv/npc/npc_itemshop.c`.

8.5 原版服务端源码包提供完整类型枚举和运行逻辑, 但当前源码树不包含完整
`gmsv/data` 道具配置. 完整道具记录必须以 8.0 的 `itemset6.txt` 为准, 不能把
“服务端逻辑完整”误解为“同一源码包也包含完整配置表”.

`itemset6.txt` 的正确文本编码为 GB18030. 读取时必须按 GB18030 严格解码, 输出文本
再统一为 UTF-8.

## 映射关系

当前客户端数据实测采用以下链路:

```text
BMP 数字文件名
  -> 资源帧号
  -> adrn_136.bin 第 frame_id 条 80 字节记录
  -> 记录内偏移 76-79 的 uint32 little-endian
  -> itemset6.txt 的 imagenumber
  -> itemset6.txt 的内部道具 ID 和详细字段
```

等价偏移公式:

```text
imagenumber_offset = frame_id * 80 + 76
```

该结论已用多个已知道具交叉验证. 这是针对当前 `adrn_136.bin` 的实测格式, 更换客户端
版本或 ADRN 文件后必须重新用已知道具验证, 不能直接假定记录布局不变.

## 分类口径

“道具总表”的 `分类` 列采用双轨格式:

```text
实际上级分类.实际具体用途.原版type数字
```

- 前两段表达配置和运行行为证明的实际语义.
- 末尾数字原样保留 `itemset6.txt` 的技术 type, 便于回查服务端分支.
- 原版 type 常量名与实际用途冲突时, 不覆盖原始 type, 也不再用常量名机械替代实际用途.
- 判定证据优先级为: 服务端运行行为和装备槽位 > `usefunc` 与合成字段 > NPC 脚本条件
  > 名称与帧图片.
- `imagenumber` 和帧图片可以被多个道具共享, 图片只能作为辅助证据, 不能单独决定分类.

全部 51 种当前分类的含义、数量、原版常量、判定依据、边界和示例见工作簿
“分类说明”. 全部 1445 条旧值、新值、修正原因和证据见“分类修正”.

## 历史 CSV 字段说明

以下字段说明用于解释早期完整导出结构. 对应 CSV 和生成器当前不在仓库中, 不能直接按
旧文件名执行重新生成.

### 映射表

- 资源路径: `资源相对路径`, `资源分类`, `资源文件名`.
- 映射键: `资源帧号`, `ADRN图号`.
- 结果: `匹配状态`, `匹配道具数`.
- 一对多摘要: `内部道具ID列表`, `道具名称列表`, `itemset源行列表`.

### 详情表

详情表首先保留资源帧、ADRN 图号、同图号匹配数和 `itemset` 源行号, 随后展开
`itemset6.txt` 的全部 94 个原始字段.

服务器源码中共有 79 个逻辑配置项. 其中 15 个 `ITEM_getRandomValue` 项在文本内各占
最小值和最大值两列, 因此原始文本实际为 94 列. 详情表将这些列明确展开为
`attack_min/attack_max`, `defence_min/defence_max` 等字段, 避免后续字段错位.

字段主要分组:

- 基本资料: `name`, `secretname`, `effectstring`, `argument`, `id`, `imagenumber`,
  `cost`, `type`, `fieldtype`, `target`, `level`.
- 回调函数: `initfunc` 至 `relifefunc`, 以及使用、装备、丢弃和拾取相关函数.
- 装备属性: 攻击次数、攻击、防御、敏捷、HP、MP、运气、魅力、回避、属性值.
- 魔法和异常状态: `magicid`, `magicprob`, `magicusemp`, 毒、麻痹、睡眠、石化、
  酒醉、混乱、必杀等最小值和最大值.
- 行为限制: 登出掉落、落地消失、叠加、宠物邮件、合并方向等标志.
- 合成材料: `ingname0/ingvalue0` 至 `ingname4/ingvalue4`.

## 边界和注意事项

- `imagenumber` 不是唯一道具键. 多个道具可以共享同一图片, 输出必须保留全部匹配.
- “无道具记录”只表示当前 `itemset6.txt` 未使用该 ADRN 图号. 资源可能属于其他版本、
  其他配置文件或当前未启用内容, 不能直接判定为无效图片.
- 本次未使用旧的 `history.txt` 作为主映射依据, 因为当前 ADRN 与当前
  `itemset6.txt` 的直接关联更可靠.
- 详情表保留 `itemset源行`, 可回到原始配置逐条核对.
- 当前分类审计保留 2748 个唯一 PNG 的原始内容和像素内容, 6945 个图片引用和
  15153 个绘图锚点均未变化. 表格导出器会把共享媒体展开为逐引用副本, 因此 XLSX
  体积会增大, 但不表示新增或丢失帧图片.
- “结论汇总”中 22 个跨中文标签公式使用标准单引号引用 `'全部资源'!`, 以兼容 Excel
  和当前表格计算引擎. 公式口径和缓存值未改变.

## 维护说明

当前仓库没有 `docs/generate_item_reference_8_0.py`, 也没有可直接执行的完整再生成命令.
维护时不得引用不存在的脚本或用临时数据掩盖缺失流程. 推荐按以下顺序处理:

1. 只读解析资源目录、`adrn_136.bin` 和 GB18030 编码的 `itemset6.txt`.
2. 用 8.5 原版枚举和运行逻辑解释技术 type, 用 8.0 配置及 NPC 脚本判定实际语义.
3. 同步更新“道具总表”分类、“分类说明”和“分类修正”, 保留逐行证据.
4. 验证工作簿结构、数据行数、关键 ID、公式错误、唯一媒体内容、图片引用和绘图锚点.
