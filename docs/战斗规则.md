# 石器时代8.5战斗规则

本文档与同目录的战斗.proto共同构成战斗系统实现权威. 仅依赖这两个文件, 应能实现从发起战斗、回合命令、8.5数值结算、客户端播放到战斗结束通知的完整系统.

## 1. 权威范围和冲突处理

### 1.1 权威顺序

发生冲突时按以下顺序处理:

1. 8.5服务端源码当前启用宏分支.
2. 本文档对现代Actor边界、超时和胜负原子边界的已确认决策.
3. 战斗.proto中的结构化枚举、消息和技能配置目录.
4. D:\csa_8.0配置和历史8.0技能资料.
5. 旧文档和旧字符串协议说明.

8.5源码根目录固定为:

D:\石器资源\石器时代-解压缩使用版\石器时代8.5的服务端源码LINUX下开发\85

核心证据文件:

- gmsv/include/version.h: 当前启用宏.
- gmsv/include/battle.h: 战斗命令、模式、标志和结构.
- gmsv/include/battle_event.h: BATTLE_ST、BATTLE_MST、BATTLE_MD状态定义.
- gmsv/battle/battle.c: 战斗创建、回合状态机、排序、合击、多段、技能分发、胜负和结束.
- gmsv/battle/battle_event.c: 命中、闪避、伤害、暴击、反击、光镜守、捕获和逃跑.
- gmsv/battle/battle_magic.c: 战斗魔法目标、效果、魔法伤害和魔法闪避.
- gmsv/battle/battle_item.c: 战斗道具.
- gmsv/battle/pet_skill.c: 宠物技能注册和命令生成.
- gmsv/battle/profession_skill.c: 职业技能注册和处理.
- gmsv/magic/magic.c和magic_base.c: 魔法注册和直接使用入口.
- gmsv/callfromcli.c和gmsv/lssproto_serv.c: 旧客户端命令入口, 仅用于理解行为, 不移植字符串协议.

### 1.2 必须保留的8.5兼容怪癖

不得以修复、简化或浮点重写的方式改变以下行为:

- 弓可以得到暴击标志, 但伤害仍调用普通BATTLE_DamageCalc, 不追加近战暴击伤害.
- 弓在闪避公式中连续两次增加20, 实际给目标闪避率增加40.
- 普通状态魔法可能先产生动画, 再因目标已有其他普通状态而拒绝写入.
- 投掷攻击选中镜反应时, 镜不触发也不消耗, 并且不会继续降级尝试陷阱或针刺.
- qsort在行动值相同时返回0, 没有稳定的阵营、站位或提交顺序次级键.
- 敌方随机攻防浮动保留原括号: (value * (rand() % 10) + 2) / 100.
- 骑乘普通伤害分摊保留两个+1写法. 最终人物伤害加骑宠伤害等于原damage+1, 不是严格守恒.
- Weaken和Barrier在BATTLE_StatusSeq中递减后又被写回cnt+1, 当前源码不按通用路径自然递减.
- 深毒剩余计数到1时直接使目标死亡.
- 攻击魔法和职业魔法的骑乘扣血中, 若计划人物伤害大于人物当前HP, 源码把扣减后的负HP暂存为charahurt, 再执行`petDamage=totalDamage-charahurt`. 因为charahurt为负数, 骑宠伤害会被额外放大, 不能改成通常的“剩余伤害”.
- 当前启用`_MAGIC_REHPAI`. 普通HP恢复不按配置中的百分号计算; 骑乘目标把一次随机恢复总量按人物与骑宠的缺血比例分配.
- 复活配置的百分号分支在非0power时会被随后`RAND(power*0.9,power*1.1)`覆盖. 只有power为0明确表示回满.
- 多数MAGIC处理器在同阵营、目标范围或战斗内细项校验前已经扣除MP. 非法目标可能消耗MP并把动作改为NoAction, 现代实现必须保留每个处理器的原顺序.
- 当前冰爆术主分发把动作登记到20项延迟队列并改为NoAction, 但队列初始化和回合执行代码均被整段注释, 因而不会释放、不会造成伤害、也不会建立冰爆状态. 不能按注释意图擅自补全.

## 2. 现代系统边界

### 2.1 服务端权威

- 一场战斗对应一个CombatRoom Actor.
- CombatRoom持有参战单位、运行期属性、状态、动作、回合计时器、随机流、事件流和最终结算.
- character只保存CombatRoom引用, 通过PostStart、PostRoundAction、PostLeave等Actor消息投递请求.
- Account负责身份和持久化边界, Gateway只转发协议, 客户端只播放并应用服务端差量.
- 客户端不得计算命中、闪避、暴击、伤害、反击、状态成功率、光镜守优先级、捕获、逃跑或胜负.
- 旧服BB、BD、BE、BM、RS等字符串可作为调试映射, 不能成为现代网络协议.

### 2.2 唯一在线协议状态机

正常状态机固定为:

1. CombatBattleStartNotify.
2. CombatRoundActionReq.
3. CombatRoundActionRes.
4. CombatRoundResultNotify.
5. CombatFlowCompleteReq和CombatFlowCompleteRes.

不引入CombatRoundPrepareNotify、Ready、ActionOption、逐回合FlowComplete或独立表现流.

CombatBattleStartNotify必须包含:

- battle_id和首回合round=1.
- 所有初始可见单位CombatUnit, 包括单位身份、阵营、站位、满HP、攻防敏、等级、元素和玩家有效运气快照.
- 不包含随机种子、随机状态、概率或需要客户端参与计算的规则参数.

CombatRoundResultNotify必须包含:

- 唯一的有序event_list.
- 每个事件的动作、段号、反击序号、合击成员序号及客户端表现效果.
- 每个效果造成的HP、存活、离场和状态差量; 客户端按顺序应用差量得到当前战场状态.
- battle_finished.
- 结束时的CombatBattleSettlement.

CombatRoundResultNotify不包含已提交或AI生成的意图、随机数、概率、公式输入、回合末完整快照或独立审计结构. 战斗未结束时, 服务端直接递增round并继续接收角色和宠物分别提交的下一回合动作, 不发送新的回合准备通知.

### 2.3 不使用回放档案

- 不定义BattleReplayArchive或同类消息.
- 不把初始快照、规则版本、随机种子和所有回合封装为独立回放档案.
- 客户端上行动作只存在于CombatRoundActionReq及服务端当前回合运行态; 正常下行结果只保留服务端产生的事件/效果.
- 随机种子和随机算法状态只存在于CombatRoom内部或服务端调试日志, 不进入普通客户端协议.

## 3. 战斗创建和开始

### 3.1 创建入口

8.5对应入口主要是BATTLE_CreateBattle、BATTLE_CreateVsEnemy和BATTLE_CreateVsPlayer. 现代实现必须在创建CombatRoom前完成所有无副作用校验:

- 发起角色在线且不在其他战斗.
- 目标战斗类型合法.
- PVE敌组、NPC脚本和地图条件存在.
- PVP双方及队伍状态合法.
- 参战单位数量不超过每侧10个站位.
- 所有玩家单位CombatUnitKey唯一.
- 怪物、NPC和召唤物通过pet_uuid字段使用本场临时唯一ID.

校验完成后再执行房间注册、角色房间引用写入、计时器创建和通知发送. 任一步骤失败必须显式回滚已经建立的引用和房间注册.

PVE创建对应BATTLE_CreateVsEnemy:

- 根据玩家floor、x、y取得field_no, 越界时按8.5规则重选.
- 从普通敌组、NPC脚本或道场敌组读取敌人模板.
- 创建敌人运行态并放入防守侧.
- 把发起玩家、队伍成员和各自默认宠物放入发起侧.
- 8.5会交换敌方前后5格以匹配旧客户端显示. 现代位置初始化必须得到等价最终position.
- 普通PVE、DP和Boss分别使用对应CombatBattleType.

PVP创建对应BATTLE_CreateVsPlayer:

- 发起方和目标均不在其他战斗.
- 校验duel、强制战斗地图、家族PK和AutoPK等启用分支.
- 队伍成员发起或被选中时, 按8.5规则归一到实际参战队伍.
- 双方队伍和默认宠物分别进入两个阵营.

### 3.2 初始单位和站位

- 每侧合法站位为0到9.
- 8.5全局bid中发起侧为0到9, 防守侧为10到19. 现代协议使用camp+position表示, 需要旧脚本时转换为bid=campOffset+position.
- 玩家侧0到4为人物槽, 5到9为对应宠物槽. 人物本侧position为n时, 默认宠物position为n+5.
- 玩家角色、出战宠物、骑宠、怪物和NPC必须分别建立可引用单位.
- 骑宠既参与人物合成属性和伤害分摊, 也必须能单独承载HP、死亡、落马和表现效果.
- 初始状态必须包含HP、MP、存活、姿态、四元素、运行期攻防敏、装备耐久、骑乘和变身.
- 宠物owner_unit_key指向主人.
- CombatUnitAttribute保留现有协议公共字段, 并补充8.5公式直接使用的level、max_hp、max_mp和CombatLuckSnapshot. 运气快照必须同时保存基础运气、装备修正合计和有效运气.

### 3.3 初始化顺序

对应battle.c的BATTLE_Init和BATTLE_PreCommandSeq:

1. 创建双方Entry和单位运行态.
2. 执行属性合规化和战斗参数初始化.
3. 初始化职业被动、装备修正、骑乘和特殊宠物状态.
4. 计算先制阵营.
5. 清空本轮guardian关系.
6. 建立第一轮命令等待状态.
7. 发送CombatBattleStartNotify.

### 3.4 先制

对应battle_event.c的BATTLE_SurpriseCheck:

| 队长有效运气 | 己方先制a | 敌方先制窗口b |
|---:|---:|---:|
| 5 | 20 | 0 |
| 4 | 15 | 2 |
| 3 | 10 | 3 |
| 2 | 5 | 5 |
| 其他 | 0 | 7 |

抽取RAND(1,100). roll<=a时己方先制, a<roll<a+b时敌方先制. 先制只作用于第一轮, 第一轮结束清除BSIDE_FLG_SURPRISE. 处于先制侧的宠物本轮跳过BATTLE_PetLoyalCheck.

### 3.5 基础运气、装备修正和有效运气

8.5同时存在两种不能混用的角色运气:

- 基础运气为`CHAR_LUCK`, 持久化在角色档案中, 正常范围1-5.
- 装备运气修正为本次从所有当前已装备物品配置读取的`ITEM_MODIFYLUCK`之和. 配置值允许为负数或远超1-5, 但不写入装备实例或角色档案.
- 有效运气为`CHAR_WORKFIXLUCK=clamp(CHAR_LUCK+sum(ITEM_MODIFYLUCK),1,5)`.
- `CHAR_complianceParameter`先把基础运气复制到工作值, `ITEM_equipEffect`再累计装备修正并执行1-5截断.
- 只有实际位于装备槽的物品参加累计. `ITEM_OTHER`和`ITEM_DISH`不能装备, 即使配置的luck列非0也不参加.
- 当前启用`_TAKE_ITEMDAMAGE`分支不会按剩余耐久比例逐渐衰减运气修正. 装备仍在槽内时每次读取完整配置修正; 装备被移除或销毁后才从合计中消失并重新合规化.

战斗判定使用哪一种运气固定如下:

| 战斗机制 | 使用值 | 8.5约束 |
|---|---|---|
| 开战先制 | 有效运气 | 读取玩家侧0号位队长的`CHAR_WORKFIXLUCK` |
| 普通物理闪避 | 有效运气 | 仅玩家防守者加入; 合击跳过闪避, 因而不读取运气 |
| 物理暴击 | 有效运气 | 仅玩家攻击者加入 |
| 玩家反击 | 有效运气 | 执行反击的玩家加入 |
| 通用普通异常状态 | 有效运气 | 攻击者加入; 麻痹专用基础值分支不加入运气 |
| 捕获 | 有效运气 | 捕获者加入 |
| PVE逃跑 | 有效运气 | 逃跑者决定分段公式 |
| 普通攻击魔法闪避 | 基础运气 | 玩家目标读取`CHAR_LUCK*3`, 装备修正不参与 |
| 职业魔法闪避 | 基础运气 | 玩家目标读取`CHAR_LUCK*3`, 装备修正不参与 |
| 10级以上玩家空手随机多段 | 基础运气 | 读取攻击者`CHAR_LUCK`, 装备修正不参与 |

宠物字段`CHAR_VARIABLEAI`与`CHAR_LUCK`复用同一底层枚举位置, 其语义是宠物AI/忠诚相关变量, 不是玩家运气. 玩家专用运气分支不得直接套用到宠物或敌人; 非玩家魔法闪避继续使用等级公式.

协议记录要求:

- 开战`CombatUnitAttribute.luck`携带完整`CombatLuckSnapshot`.
- 单位状态的`runtime_attribute_list`分别保存BaseLuck、EquipmentLuckModifier和EffectiveLuck.
- 装备运气不写入`CombatEquipmentRuntimeState`或`EquipmentRecord`; 服务端每次根据当前装备ID查询物品配置, 并只把本次合计写入`EquipmentLuckModifier`.
- 每次读取运气的`CombatRandomCheck`必须填写`luck_usage`和判定时的`luck_snapshot`.
- 装备被移除、销毁或换装后, 服务端先重算运气快照, 后续判定只能读取新值.

## 4. 回合状态机

### 4.1 命令收集

1. CombatRoom只接受匹配battle_id、当前round和可控unit_key的请求.
2. 同一单位第一份合法动作锁定, 后续请求不能覆盖.
3. 目标和资源只做提交阶段可判定的合法性检查. 真正执行前必须再次解析目标.
4. CombatRoundActionRes广播动作已接收, 不提前广播随机结果.
5. 角色和宠物分别提交动作; 不使用整回合批量提交、Ready、Prepare或CombatRoundContext.
6. 所有玩家可控单位提交完成或服务端超时后, 才生成敌方AI动作.

### 4.2 超时

现代超时规则固定为:

- 玩家角色补CombatActionType_Defense.
- 玩家宠物直接补CombatActionType_Defense, action_id=9000003, 不读取技能槽也不要求配置防御技能.
- 宠物主动待机仍可由客户端提交, 使用CombatActionType_Wait和action_id=9000001; 超时不补待机.

8.5的_BATTLECOMMAND_TIME在本侧至少一名玩家已提交动作后才设置`PartTime=time(NULL)+120`; 到期时把仍为CommandWait的玩家设为BATTLE_COM_COMPELESCAPE并立即强制离场. 该行为只作为LegacyBattleRule_CommandTimeoutForcedExit记录, 不进入现代主流程.

### 4.3 回合预处理

每轮开始对应BATTLE_PreCommandSeq:

- guardian字段重置为-1.
- 清除CHAR_BATTLEFLG_GUARDIAN.
- 地球一周等待态除外, 对单位执行CHAR_complianceParameter.
- 攻击、防御、敏捷和魅力临时mod通过BATTLE_TurnParam衰减.
- 普通临时mod每轮保留80%, 即原值乘0.8后按C赋值截断.
- CHAR_BATTLEFLG_REVERSE存在时交换地和火、水和风.

### 4.4 AI生成

玩家命令齐全后调用双方BATTLE_ai_all. AI可以读取已锁定动作和当前状态, 但产生的动作只写入服务端当前回合内部动作结构, 经过与玩家动作相同的合法性、目标解析、顺序计算和事件生成流程, 不作为intent下发客户端.

当前PVE基础AI由`pet.yaml battleAI`配置. `attackWeight`、`defenseWeight`、`escapeWeight`是非负相对权重, 总和为0时直接防御; `targetScope`和`targetSelection`只在选择普通攻击时生效. 逃跑是基础动作, 不是宠物技能.

### 4.5 单位行动前状态顺序

单位轮到行动时严格依次执行:

1. BATTLE_StatusSeq.
2. BATTLE_MagicStatusSeq.
3. BATTLE_ProfessionStatusSeq.
4. BATTLE_CanMoveCheck.
5. 最终动作改写和目标解析.
6. 执行动作及其必要后处理.

状态跳数致死或不能行动时, 服务端内部把动作改为Wait/None, 并在有客户端表现需要时生成Status或Wait事件; 不下发独立IntentRewrite列表.

### 4.6 动作原子边界和胜负检查

一个单位动作的原子范围包括:

- 多段攻击的全部已执行段.
- 每段光、镜、守、陷阱、针刺处理.
- 忠犬改向和骑宠分摊.
- 睡眠唤醒、装备耐久、落马、击飞、死亡和状态追加.
- 整个动作完成后最多5次的交替反击链.
- 必要的返回原位和倒地效果.

上述处理完成后才检查双方有效存活数. 任意一方为0时:

- 立即终止本回合剩余行动.
- 不生成未执行动作的伤害和状态事件.
- 直接进入唯一胜负和奖励结算.

合击整体视为一个动作组. 每个成员仍独立执行AttackSeq、暴击和伤害反应, 普通合击伤害累计到最后一个实际成员后统一扣除; 光、镜、守、陷阱或针刺等成员级反应可按8.5局部条件提前停止剩余成员. 整组合击及必要后处理结束后才执行双方有效存活检查, 不在普通成员的累计伤害尚未统一扣除时提前判胜负.

## 5. 确定性随机和数值语义

### 5.1 随机流

现代实现使用每场独立的确定性随机流. 推荐固定为PCG32-XSH-RR 64/32 v1, 并把算法名、版本、64位state、64位stream和初始seed保存在服务端内部.

8.5 RAND(min,max)必须映射为闭区间:

result = min + next_uint32 % (max - min + 1)

为保持8.5取模行为, 不使用拒绝采样消除模偏差. 每个源码RAND调用恰好消费一次随机值, rand()%N也恰好消费一次. 不得因日志开关、客户端数量或表现分支增加随机抽取.

CombatRandomCheck可以记录raw_min、raw_max、raw_roll、比较符和抽取序号, 但不记录seed.

### 5.2 C数值规则

- int除法向0截断.
- float或double赋给int时向0截断.
- 复合赋值在该语句处立即转换回左值类型.
- 计算顺序严格跟随8.5语句顺序.
- 不得把多个int阶段合并成一个高精度公式后只在末尾取整.
- RAND边界为闭区间, 但成功比较必须保留每处源码的<或<=.
- 所有协议delta同时给出before、delta和after, after是服务端最终权威值.

## 6. 行动顺序和合击组建

### 6.1 基础行动值

普通动作对应battle.c的BATTLE_DexCalc:

- work = 当前WORKQUICK + 20.
- 骑乘时先使用BATTLE_adjustRidePet3A得到合成敏捷, 再加20.
- dex = work - RAND(0, work * 0.3).
- dex<1时设为1.
- _EQUIT_SEQUENCE开启时再叠加装备顺序值.

道具动作使用`dex=int(work-RAND(0,int(work*0.3))+work*0.15)`, 即在普通随机敏捷表达式内追加15%的work, 最后写入int时截断.

攻击魔法在_BATTLE_NEWPOWER下扣除0%到30%的work.

职业技能的主要随机扣减区间:

| 职业动作 | 扣减区间 |
|---|---|
| 火/冰/雷附体 | RAND(work*0.30, work*0.50) |
| 火山泉、召雷、冰箭 | RAND(0, work*0.20) |
| 电流、火星球、冰爆 | RAND(0, work*0.50) |
| 火龙枪、暴风雨、冰镜、附身、移形换位 | RAND(work*0.20, work*0.50) |
| 世界末日 | 保留源码RAND(0.3, work*0.6)的隐式整数边界怪癖 |

疾速攻击增加30%, 暗月狂狼增加20%. 最终按行动值降序qsort. 相等时不增加稳定次级排序.

### 6.2 防御动作

防御是否生效直接读取目标已锁定的BATTLE_COM_GUARD, 不要求目标先执行一个动画动作. 因此目标即使行动值较低, 在被攻击时仍按防御结算. 防御自己的事件仍按最终事件流表现.

### 6.3 合击候选

合击在随机敏捷排序后扫描连续Entry:

- 起始判定玩家/非敌方为50%, 敌方为20%.
- 所有成员必须选择普通BATTLE_COM_ATTACK.
- 必须同阵营、同一目标、存活、可行动.
- 投掷武器不能参与.
- 后续成员必须在排序结果中连续满足条件.

## 7. 普通攻击完整管线

### 7.1 武器和目标

- 空手、斧、棒、枪使用近战单体流程.
- 弓使用远程目标展开, 按主目标列和随机方向生成顺序.
- 回力标按五人站位组和攻击方方向遍历.
- 投掷斧/石等使用投掷流程, 不触发忠犬、反击、镜、陷阱和针刺.
- ITEM_BREAKTHROW命中时把追加状态设置为麻痹.
- 目标失效时, 普通流程从目标阵营合法存活单位中随机重选. 没有合法目标才失败.

### 7.2 骑乘合成属性

对应battle_event.c的BATTLE_adjustRidePet3A和_BATTLE_NEWPOWER:

| 属性用途 | 人物系数 | 骑宠系数 |
|---|---:|---:|
| 投掷攻击力 | 1.0 | 0.4 |
| 近战攻击力 | 0.8 | 0.8 |
| 防御力 | 0.7 | 0.7 |
| 投掷方敏捷 | 0.8 | 0.2 |
| 近战方敏捷 | 0.2 | 0.8 |
| 防守方敏捷 | 0.1 | 0.9 |

函数返回float. 调用者写入int的位置必须立即截断.

### 7.3 闪避

以下情况直接不允许普通闪避:

- 目标选择Guard.
- 目标存在任意伤害反应槽.
- 目标不能移动, 世界末日特殊例外按源码.
- CHAR_BATTLEFLG_NODUCK.
- CHAR_BATTLEFLG_ABIO.

SetDuck被动可以先直接返回闪避成功.

类型修正:

- 敌人攻击宠物: 攻方敏捷乘0.8.
- 非敌人攻击宠物: 守方敏捷乘0.8.
- 非玩家攻击玩家: 攻方敏捷乘0.6.
- 玩家攻击非玩家: 守方敏捷乘0.6.

令At为修正后攻方敏捷, Df为修正后守方敏捷.

- Df>=At时, Big=Df, Small=At, wari=1.
- Df<At时, Big=At, Small=Df, wari=Small/Big.
- 通常Work=(Big-Small)/0.02.
- 目标正在施放装备魔法时使用0.027.
- per=sqrt(Work)*wari+守方玩家有效运气CHAR_WORKFIXLUCK+gBattleDuckModyfy. 非玩家守方不加角色运气.
- 攻方酒醉时per再加RAND(20,30).
- 弓分支两次各加20, 总计+40.
- per乘100后上限7500, 下限1.
- _EQUIT_HITRIGHT命中值按RAND(AddHit*0.8, AddHit*1.2)从per扣除, 最低0.
- 职业闪避继续按职业函数修正.
- 混乱攻击把当前per的40%追加回per.
- 成功条件为RAND(1,10000)<=per.

### 7.4 基础物理伤害

对应battle_event.c的BATTLE_DamageCalc, _BATTLE_NEWPOWER分支.

1. attack取骑乘合成攻击或WORKATTACKPOWER.
2. 非骑乘defense=WORKDEFENCEPOWER*0.70.
3. 骑乘defense=BATTLE_adjustRidePet3A防御结果*0.70.
4. SuperWall存在时, ratio=(OTHERSTATUSNUMS+rand()%20)/100.0, defense+=defense*ratio.
5. 目标为enemy时, defense+=(defense*(rand()%10)+2)/100.
6. 攻方为enemy时, attack+=(attack*(rand()%10)+2)/100.
7. 石化目标defense*=2.
8. Regret专用目标把defense改为FIXTOUGH.
9. 无视防御值大于1时, defense*=1-percent/100.

分段基础公式:

- defense<=attack<defense*8/7时, damage=(int)RAND(0, attack/16).
- defense>attack时, damage=RAND(0,1).
- attack>=defense*8/7时:
  - K0=RAND(0,attack/8)-attack/16.
  - damage=(int)((attack-defense)*2.0+K0).

之后严格按以下顺序:

1. 元素修正.
2. 属性结界修正.
3. 追加攻击和防御值.
4. 暴击追加伤害.
5. 技能专用倍率.
6. Guard或破防.
7. 最低伤害随机.
8. 同队误伤限制.
9. Arrange格挡.
10. gBattleDamageModyfy.
11. gDamageDiv多段除数.
12. 光镜守等伤害反应和骑乘分摊.

每个int赋值点独立截断.

### 7.5 元素

基础常量:

- AJ_SAME=1.0.
- AJ_UP=1.5.
- AJ_DOWN=0.6.
- D_ATTR=1/(100*100).

相克:

- 火克风, 弱水.
- 水克火, 弱地.
- 地克水, 弱风.
- 风克地, 弱火.
- 同属性1.0.
- 有属性攻击无属性1.5.
- 无属性攻击有属性0.6.

BATTLE_AttrCalc按攻方四元素乘守方四元素和AJ矩阵, 再乘D_ATTR.

场地单元素倍率:

power=0.5+selectedElement*fieldPower*0.01*0.01*0.5

无场地时power=0.5. 伤害先完成矩阵int截断, 再执行damage*=AtFieldPow/DfFieldPow并再次截断.

结界按地、水、火、风else-if顺序只应用第一个匹配项, 扣除damage*(攻方对应元素/200.0).

追加攻防:

other=RAND(apower*0.3,apower)-RAND(dpower*0.3,dpower)

damage+=other, 小于0时置0.

### 7.6 暴击

暴击输入为双方FIXDEX、攻方玩家有效运气CHAR_WORKFIXLUCK和武器/装备暴击值.

类型修正与根号模式:

- enemy攻击pet: divpara=10, 不开根号.
- pet攻击enemy: 守方敏捷乘0.8.
- 非player攻击player: divpara=10, 不开根号.
- player攻击非player: 守方敏捷乘0.6.
- 其他使用gCriticalPara=0.09并开根号.

令Big和Small为两敏捷较大/较小值. 攻方敏捷较大时wari=1, 否则wari=Small/Big.

- Work=(Big-Small)/divpara, 最低0.
- 根号模式per=sqrt(Work)+装备暴击*0.5.
- 非根号模式per=Work+装备暴击*0.5.
- per*=wari.
- per+=攻方玩家有效运气CHAR_WORKFIXLUCK.
- per*=100.
- per限制为1到10000.
- 雷尔特定形象101813/101814按源码免疫对应暴击/击飞判定.
- 成功条件为RAND(1,10000)<per, 注意是严格小于.

近战暴击伤害:

damage=BATTLE_DamageCalc+目标WORKDEFENCEPOWER*攻方等级/目标等级*0.5

该加法赋给int时截断. 弓暴击只保留Critical标志, 伤害仍为普通BATTLE_DamageCalc.

### 7.7 防御、破防和格挡

普通Guard抽取RAND(1,100):

| roll | 伤害倍率 |
|---:|---:|
| 1-25 | 0% |
| 26-50 | 10% |
| 51-70 | 20% |
| 71-85 | 30% |
| 86-95 | 40% |
| 96-100 | 50% |

GuardBreak2在目标防御时伤害乘1.3, 未防御时乘0.7. 目标混乱时不应用普通Guard减伤.

_EQUIT_ARRANGE成功时伤害乘0.1并返回BATTLE_RET_ARRANGE. 伤害小于1时先RAND(0,1). 伤害为0时通常表现Miss, 忠犬改向可改为Normal且伤害1, Guard则可表现AllGuard.

### 7.8 同队误伤

同侧玩家/宠物伤害默认不能把队友压到最大HP的40%以下. 混乱、挑拨、附身、低忠诚AIBAD、特殊诱惑或主人攻击自己宠物等源码例外不受限制.

若目标扣血后<=maxHP*0.40, 或maxHP*0.4<40, damage=0, 否则damage=1.

### 7.9 伤害反应优先级

五个独立槽可同时存在, 并可与普通异常和MagicTbl状态并存. 每段只选择一个:

1. Vanish, 守: 本段伤害无效, 次数减1.
2. Absorb, 光: 伤害转为目标和骑宠治疗, 次数减1.
3. Reflect, 镜: 近战伤害改由攻击者和攻击者骑宠承受, 次数减1.
4. Trap, 陷阱: 近战攻击者承受WORKMODTRAP预存值, 触发后状态和值清零.
5. Acupuncture, 针刺: 先把奇数原伤加1变成偶数. 目标承受该偶数伤害; 无骑宠攻击者承受`damage/2`, 有骑宠时先按骑乘防御比例和`+1`怪癖拆分、各自补成偶数后再各除2. 触发后清零.

同类光/镜/守重施直接覆盖剩余触发次数. 例如已有5次镜再施加3次, 最终为3, 不是8或5.

投掷攻击特殊规则:

- 镜不能反射.
- 陷阱和针刺不触发.
- 若当前最高优先级是镜, 代码把react设为None并结束该分支, 不继续选择更低优先级槽.

合击可以命中带光、镜、守的单位. 每个合击成员重新读取并可能消耗一个最高优先级槽. 合击只跳过忠犬Guardian替身和普通闪避, 不跳过光镜守.

### 7.10 骑乘分摊、死亡和击飞

普通分摊前把人物和骑宠防御最低视为1:

playerDamage=(damage*petDefense)/(charDefense+petDefense)+1

petDamage=damage-playerDamage+1

因此两者合计为damage+1. 各自HP独立限制到0和最大HP. 骑宠死亡立即解除骑乘.

击飞/绝技阈值:

- 单次直接伤害>=maxHP*1.2+20时产生第二类Ultimate.
- 累计过量伤害达到同阈值时产生第一类Ultimate.
- 雷尔特定形象按源码免疫.

### 7.11 睡眠、状态追加和装备耐久

- 实际有效伤害调用BATTLE_DamageWakeUp清除睡眠.
- Absorb和Vanish不视为有效伤害, 不唤醒.
- 只有damage>0时执行命中追加状态.
- 只有damage>0时执行BATTLE_ItemCrushCheck.
- 装备耐久下降、破损和移除必须作为CombatEquipmentDelta下发.

## 8. 多段攻击

### 8.1 本质

三段、十段和其他连续技能仍然是重复调用物理攻击管线. 每段可以有不同临时攻击力、目标、闪避、暴击、伤害反应和最终伤害. 不是把一个总伤害简单拆成客户端数字.

### 8.2 段数来源

武器ITEM_ATTACKNUM_MIN/MAX存在时, 段数为闭区间RAND(min,max), 小于等于0改为1.

无武器配置且玩家等级>=10时:

- luckWork=LUCK*5, 上限25.
- roll=RAND(1,1000).
- roll<=10+luckWork: RAND(5,10)段.
- roll<=30+luckWork: 3段.
- roll<=70+luckWork: 2段.
- 否则1段.

### 8.3 伤害除数

- 空手/Fist多段: gDamageDiv=段数.
- ContinuationAttack: gDamageDiv=段数.
- WildViolentAttack: RAND(3,10)段, gDamageDiv=段数.
- AttackShoot丢栗子: 段数来自技能参数, gDamageDiv=段数.
- AttackCrazed疯狂暴走: 段数来自高位COM3, gDamageDiv保持1, 每段不均分.

每段调用BATTLE_Attack. 当前攻击者死亡、没有合法目标或动作被终止时停止剩余段.

### 8.4 反击上限

反击循环位于整个多段主动动作之后, 不在每段之后. battle.c主循环最多执行5次BATTLE_Counter, 双方交替成为攻击者.

因此:

- 三段攻击整次动作最多5次反击, 不是15次.
- 十段攻击整次动作最多5次反击, 不是50次.
- counter_index为1到5.
- counter_depth可表达反击、反击的反击和继续交替的更深链.

## 9. 反击

### 9.1 资格

- 双方HP必须大于0.
- 被检查单位原命令只允许BATTLE_COM_ATTACK或BATTLE_COM_S_NOGUARD.
- CHAR_BATTLEFLG_ABIO不能反击.
- 任一方使用投掷武器不能反击.
- 任一方使用丢栗子不能反击.
- 光镜守存在时本次反击仍可按源码进入, 但BATTLE_Counter返回值会终止后续扩展链.

### 9.2 基础反击率

BATTLE_CounterCalc:

- enemy攻击pet: divpara=10, 不开根号.
- pet攻击enemy: 守方敏捷乘0.8.
- 非player攻击player: divpara=10, 不开根号.
- player攻击非player: 守方敏捷乘0.6.
- 其他divpara=gCounterPara=0.08并开根号.

攻方敏捷>=守方时wari=1, 否则wari=Small/Big.

Work=(Big-Small)/divpara, 最低0.

- 根号模式base=sqrt(Work).
- 非根号模式base=Work.
- base*=wari.

玩家:

- 读取8x8 CounterTbl武器相性.
- per=base*weaponValue*0.1+执行反击玩家的有效运气CHAR_WORKFIXLUCK.
- _SUIT_ADDENDUM开启时再加WORKCOUNTER.
- per*=100, 最低随机阈值1.
- 成功条件RAND(1,10000)<per.

宠物:

- per=base.
- NoGuard追加其反击修正.
- per上限100.
- per*=100, 最低1.
- 成功条件RAND(1,10000)<=per.

### 9.3 反击伤害

反击先独立调用BATTLE_AttackSeq, 然后damage*=0.75, 正伤害最低1, 再进入BATTLE_DamageSub和光镜守/骑乘分摊. 每次反击必须生成独立CombatEvent, parent_event_id指向上一触发事件, counter_index和counter_depth按实际顺序递增.

### 9.4 反击击倒表现

若A走到B面前攻击, B反击并使A倒地:

1. 反击Damage效果在逻辑上完成.
2. 生成A的ReturnHome移动效果.
3. 生成A在home_position的Knockdown或Death效果.

客户端必须按两个CombatEffect顺序播放. 不能让A直接倒在B面前, 也不能用一个含糊的击倒标志让客户端猜测.

## 10. 合击

### 10.1 成立条件

- 所有成员主动选择普通攻击.
- 成员在最终行动排序中连续.
- 同阵营.
- 同一目标.
- 成员存活并可行动.
- 非投掷武器.
- 起始随机判定成功.

### 10.2 每个成员的独立判定

- 按排序后的成员顺序执行.
- 每个成员独立计算攻击力和目标防御.
- 每个成员独立判定暴击.
- 每个成员独立检查并消耗光、镜、守、陷阱或针刺.
- 每个成员有自己的子CombatEvent和独立伤害表现; 普通成员的HP差量只在最后一个实际成员统一应用累计值.
- 合击不执行普通闪避判定, 因此不是“闪避率为0”, 而是根本没有Dodge随机抽取.
- 合击初始化Guardian=-2, 因此不触发忠犬替身.
- 目标选择防御时, 防御仍参与每个成员伤害.
- 合击完成后不再进入普通多段动作的反击循环.

8.5原字符串流程会累计普通合击伤害后统一BATTLE_DamageSub2, 但每个成员的AttackSeq、暴击和反应是独立的. 现代事件流保留成员级结果, 普通伤害必须在最后一个实际成员统一扣除, 整组合击作为一次动作边界检查有效存活. 若成员级光、镜、守、陷阱或针刺反应已经使目标或当前成员死亡, 按8.5的局部循环条件停止剩余成员, 再完成必要后处理和胜负检查.

### 11.6 状态冲突和叠加

| 场景 | 8.5结果 |
|---|---|
| 石化5回合后施加睡眠3回合 | 拒绝睡眠, 保留石化5的当前剩余值 |
| 石化5回合后再施加石化3回合 | 拒绝新石化, 不变成8、3或max(5,3) |
| 任意BATTLE_ST存在后走通用状态施加或普通职业状态施加 | 扫描到已有状态后失败; 新状态不覆盖、不叠加 |
| 目标已有石化时施加自然威能 | 可以成功, 因专用分支只检查火/冰/雷单抗; 随后同时写三个单抗槽为turn+1 |
| 已有火、冰或雷任一单抗时施加自然威能 | 失败; 另外两个空单抗也不写入 |
| 正常使用冰爆术 | 只登记已失效的延迟队列并NoAction, 不建立任何冰爆槽 |
| DefMagic存在后施加SuperWall | MagicTbl互斥检查失败 |
| 守和镜同时存在 | 可以并存 |
| 石化和镜同时存在 | 可以并存 |
| 镜5次后重施镜3次 | 直接覆盖为3次 |
| 守、光、镜、陷阱、针刺同时存在 | 可以并存, 每段只消耗实际选中的最高优先级槽 |

通用BATTLE_StatusAttackCheck在组扫描之后才调用RAND, 因此该路径的组冲突不消费状态概率随机值. PROFESSION_BATTLE_StatusAttackCheck相反, 进入函数第一句就执行`rand_num=RAND(1,100)`, 所以非法状态、目标死亡、组冲突以及自然威能专用成功/失败都先消费一次随机值. 旧MultiStatusChange可能在冲突检查前已经输出动画, CombatStatusDetail必须标记visual_effect_played_before_conflict_check.

### 11.7 普通状态成功率

BATTLE_StatusAttackCheck先扫描全部BATTLE_ST. 有任何正值立即失败.

麻痹特殊基础值为20-目标麻痹抗性.

其他状态:

- vitalShare=VITAL/(VITAL+STR+TOUGH+DEX).
- SARS使用(1-vitalShare)*0.9.
- fVitalP=(vitalShare/0.25)*10.
- 非PVP等级差=(攻等级-守等级)*Bai, 并限制在正负Range.
- PVP等级差为0.
- per=PerOffset+等级差+攻方有效运气CHAR_WORKFIXLUCK-目标状态抗性-fVitalP-全局/装备/套装抗性. 麻痹使用前述专用基础值, 不加入运气.
- per上限80, 源码没有统一下限.
- 成功条件RAND(1,100)<per, 严格小于.

职业状态使用PROFESSION_BATTLE_StatusAttackCheck: 先无条件抽`rand_num=RAND(1,100)`, 再校验状态范围、目标HP/死亡和冲突, 普通成功条件为`rand_num<Success`. 自然威能状态码31是专用分支: 只要25/26/27任一已有值就失败, 否则无视其他BATTLE_ST并直接成功; 成功写入的是25/26/27三个槽的`turn+1`, 不是槽31. 函数中用状态码与`CHAR_WORKICECRACK*`字段号比较的冰爆提前成功分支因前置`status<BATTLE_ST_END`而不可达.

### 11.8 状态跳数伤害

普通Poison:

- sum=VITAL+STR+DEX+TOUGH.
- damage=((sum/100)-20)/4.
- damage<1时改为1.
- damage不能把人物或骑宠降到0, 最低保留1HP.

DeepPoison:

- 行动前HP<=1时直接置0并死亡.
- 剩余计数<=1时直接置0并死亡.
- 其他跳数使用普通四维毒伤公式并保留1HP.
- 骑乘时人物和骑宠分别按自己的四维计算.

SARS:

- 人物damage=currentHP*10/100, 最低保留1HP.
- 骑宠部分仍使用普通四维毒伤.

## 12. 其他主动动作

### 12.1 等待

Wait不产生主动伤害. 仍要完成行动前状态跳数、动作改写事件和动作原子边界胜负检查.

### 12.2 魔法

#### 12.2.1 入口、扣MP和目标

MAGIC_DirectUse先检查NoCast, 再从装备槽或宠物技能参数取得item实例、magic_id、MAGIC配置和处理器. MP取ITEM_MAGICUSEMP. 家族光/暗精灵对指定magic数组范围乘MP_RATE.

必须保留以下调用顺序:

1. 各MAGIC处理器拒绝BATTLE_CHARMODE_INIT.
2. 检查当前MP是否足够.
3. 多数处理器立即扣除MP.
4. 才进入战斗内同阵营、目标范围、配置参数和具体效果校验.
5. 因此非法敌我目标可能已经消耗MP. `_PREVENT_TEAMATTACK`分支还会把本次动作改为NoAction.

普通攻击魔法仅人物扣MP. 宠物执行MAGIC_AttMagic不扣MP. 目标必须由BATTLE_MultiList和ATTMAGIC的5x3范围模板展开, 然后按SortLoc排序. 单体模板以目标为中心裁剪; 20和21表示整侧; 23到26表示指定行. 客户端不得按magic option自行扩展目标.

#### 12.2.2 普通攻击魔法命中和伤害

当前启用`_FIX_MAGICDAMAGE`、`_EQUIT_DEFMAGIC`和`_MAGIC_DEFMAGICATT`. 一次施法先计算攻击魔法等级:

- 玩家: 对应元素的CHAR_EARTH_EXP+element.
- 敌人: int(level*0.9).
- 宠物: 对应元素EXP, 并按玩家型魔法处理.

整次施法只取一次`trueRoll=rand()%100`. `TrueMagic=(trueRoll<=attackMagicLevel)`, 所有目标共用. TrueMagic失败不会Miss, 而是在目标最终元素伤害后乘0.7并向0截断.

每个目标的对应元素抗性:

- 玩家: `base=CHAR_EARTH_RESIST[element]`, 再加`CHAR_EQUITDEFMAGIC_E[element]`.
- 敌人: `int(level*0.5)`.
- 宠物: 自身对应元素RESIST, 不加人物装备抗性.
- 若DEFMAGICSTATUS存在且当前抗性大于0, `resist=int(resist+resist*OTHERSTATUSNUMS/100)`.

魔法闪避独立于TrueMagic. 玩家阈值为:

`magicDodge=int(baseLuck*3 + elementResist*0.15 + EQUITQUIMAGIC*0.9)`.

这里的`baseLuck`严格读取玩家`CHAR_LUCK`, 不读取`CHAR_WORKFIXLUCK`, 所以装备`ITEM_MODIFYLUCK`不提高普通攻击魔法闪避.

非玩家阈值为`min(level*0.2,30)`. 每目标取`roll=rand()%100+1`, `roll<=magicDodge`即Miss. Miss目标伤害为0, 不进入伤害公式, 也不在本次攻击魔法结束时解除睡眠.

未闪避目标按以下顺序计算, 每个赋给int的步骤都向0截断:

```text
Kmagic = max(float(attackMagicLevel)*1.4-float(defenderResist), 0)
Mmagic = max(float(attackMagicLevel), 1)
Amagic = Kmagic*Kmagic/(Mmagic*Mmagic)
Amagic += float(rand()%20)/100
APower = int(Power*(1+float(MagicLv)/10)*Amagic)
damage = BATTLE_getMagicAdjustInt(attacker, defender, MagicLv, element, APower)
if !TrueMagic: damage = int(damage*0.7)
```

`BATTLE_getMagicAdjustInt`的元素步骤:

1. 取攻击者四属性. 骑乘时每项为`int((character+pet)/2)`. 负值归0. 无属性为`max(100-四属性和,0)`.
2. `spellValue=MagicLv*10`.
3. 仅指定元素改为`spellValue+spellValue*int(originalElement/50)`. 其他三个有属性清0. 源码没有清零At_none, 必须保留原无属性值.
4. 用修改后的攻击属性计算攻击侧场地倍率.
5. 五项攻击属性分别乘APower, 再与目标五属性进入BATTLE_AttrCalc元素矩阵.
6. `damage=int(matrixDamage*attackerFieldPower/defenderFieldPower)`.

命中的睡眠目标在整次施法伤害结束后清除Sleep. 经验成长只在源码对应玩家/宠物分支发生, 不得让客户端参与.

#### 12.2.3 攻击魔法骑乘分摊

无骑宠时ratio=10. 无元素调用时ratio=5. 有元素时分别对人物和骑宠计算:

```text
effect = clamp(int((100*positiveElement-100*sameElement)/1000), -10, 10)
weight = 20+effect
ratio = clamp(int(10*characterWeight/(characterWeight+petWeight)), 2, 8)
plannedCharacterDamage = int(totalDamage*ratio/10)
```

positiveElement使用`(spellElement+1)%4`, sameElement使用spellElement. 骑宠计划伤害为剩余值.

必须保留HP不足怪癖. 源码先执行`characterHP-=plannedCharacterDamage`. 若结果小于0, 把这个负数赋给临时charahurt, 人物HP置0, 再执行`petDamage=totalDamage-charahurt`. 因charahurt为负, petDamage会大于totalDamage. 协议用CombatMagicDamageFormulaTrace同时记录计划分配和实际HP变化. 骑宠HP降到0时立即落马、恢复人物形象并设置PETFALL.

#### 12.2.3.1 召龙魔法

MAGIC_ToCallDragon不是召唤单位入场. 入口在校验MP后立即扣MP, 非战斗场景随后返回失败但不退MP. 战斗内option格式为`imageNo|power`, 然后调用BATTLE_MultiToCallDragonMagic:

1. `FieldAttr`局部变量初始化为-1, 旧属性解析代码已被注释, 因而所有当前召龙配置都以-1传入.
2. 每个目标临时创建形象100354、等级100、幸运1的计算角色, 只写`WORKATTACKPOWER=power`和`WORKOTHERDMAGE=0`.
3. 先调用BATTLE_MagicDodge. 玩家分支会读取`CHAR_EARTH_RESIST+(-1)`, 即枚举中地抗前一个字段; 非玩家仍用`min(level*0.2,30)`. 这是当前源码的越位字段语义, 不能擅自改成某个元素抗性.
4. 未闪避时调用普通`BATTLE_DamageCalc(临时角色,目标)`, 不调用普通攻击魔法公式, 也不计算暴击、忠犬、光镜守或反击.
5. 无骑宠时全伤扣人物. 有骑宠且FieldAttr=-1时BATTLE_CalcCharaRatio固定返回5, 即计划人物一半、骑宠剩余一半; 人物HP不足时沿用第12.2.3节的负数剩余伤害怪癖.
6. 骑宠HP到0立即落马. 每个目标必须输出自己的Dodge或Damage、人物/骑宠分配和FallMount效果.

目标代码20和21分别展开两侧全体. 23/24的循环都覆盖CharTable第0、1行, 25/26都覆盖第2、3行; 因边界限制, 同侧两个“行”代码在当前实现中实际展开为同一个整侧集合. 目标按SortLoc排序后结算.

#### 12.2.4 恢复和复活

恢复option由`atoi`取得power, 含`%`只设置per标志. 每个目标先取`RAND(int(power*0.9),int(power*1.1))`.

当前启用`_MAGIC_REHPAI`:

- 无骑宠HP恢复: 实际基础量就是上述随机值, `%`不按最大HP计算.
- 有骑宠HP恢复: 随机值是总恢复池. `charMissing=maxHP-HP`, `petMissing=maxHP-HP`, `allMissing=charMissing+petMissing`, 小于等于0时改为1. `charPercent=int(charMissing*100/allMissing)`, 人物分到`int(pool*charPercent/100)`, 骑宠得到剩余值.
- MP恢复不走骑宠分摊, 仍按随机值增加并受最大MP限制.
- HP恢复受CHAR_CanCureFlg检查. 恢复死亡单位的HP不会自动清除ISDIE.

复活使用BATTLE_MultiListDead, 仅处理ISDIE=true的目标. PVP中的玩家目标被直接跳过. `power==0`时恢复到最大HP. 非0时即使参数含`%`, 先算出的百分比也被`RAND(int(power*0.9),int(power*1.1))`覆盖, 然后最低取1并限制到最大HP, 最后清除ISDIE. 复活守精在相同复活后直接把指定光/镜/守槽覆盖成配置次数. PVE宠物复活还触发AI_FIX_PETRESSURECT.

#### 12.2.5 状态、光镜守、参数和场地魔法

- 通用状态魔法默认turn=3、Success=15, 从option扫描BATTLE_ST名称及可选turn、成功参数, 再调用第11.7节的状态公式. DeepPoison处理器把配置turn额外加2.
- 普通状态成功后直接写`StatusTbl[status]=turn`. 麻痹、睡眠、石化和Barrier同时清空目标当前动作. 已有普通状态导致失败时, 魔法视觉效果可能已经播放.
- MagicStatus option格式为`status|turn|nums|范围`. 施加前扫描全部MagicTbl[1..]. 只要已有任意魔法状态就拒绝新状态; 同状态也不刷新、不覆盖. 成功时写turn, 并把共享数值写入OTHERSTATUSNUMS.
- 状态恢复先扫描目标全部BATTLE_ST并保留最高ID的非0状态. 每次最多清除这一个状态. 配置status=0只通配ID1到6, 即Poison、Paralysis、Sleep、Stone、Drunk、Confusion; 不通配ID7以上状态. 指定状态必须等于该最高ID状态. NoCast被清除时另发沉默解除通知.
- 光、镜、守分别位于独立MagicDefTbl槽. 施加时不检查其他槽, 直接把本槽覆盖为count. 因此守护和镜子可以并存, 受击时仍按第11.4节优先级只选择一个反应.
- 参数魔法的攻、防、敏百分比分支分别累加`FIXSTR*power`、`FIXTOUGH*power`、`FIXDEX*power`到以百分之一为单位的MOD槽; 非百分比分支累加`power*100`. 魅力百分比分支为`int(FIXCHARM*power*0.01)`, 捕获始终直接累加power.
- 属性反转用XOR切换REVERSE标志并立即执行一次地火、水风互换; 再次使用会切回.
- 场地魔法解析无、地、水、火、风, power默认30且只接受0到100, turn默认3. 新场地直接覆盖field_att、att_pow和att_count, 不叠加旧场地回合.

#### 12.2.6 职业魔法等级和基础功率

魔法型职业等级M按原熟练度转换: `>90=10, >80=9, ..., >10=2, 其他=1`. 物理型等级A为`>=100=10, >90=9, ..., >10=1, 其他=0`. 边界的`>`和`>=`不可统一.

当前`_PROFESSION_ADDSKILL`下, PROFESSION_MAGIC_GET_PRACTICE的hp_power如下:

| 技能 | 级别到基础hp_power |
|---|---|
| 火山泉 | `grade*10+100`; grade10功率暴击阈值25, 其他为grade+12; `RAND(1,100)<=阈值`时乘1.5 |
| 火星球 | 1-2:160, 3-4:180, 5-6:220, 7:260, 8:280, 9:320, 10:360 |
| 召雷术 | `grade*10+200` |
| 电流术 | 1:50, 2-4:10, 5-7:150, 8-9:200, 10:300; 源码中的250分支不可达 |
| 暴风雨 | 1-3:120, 4-5:140, 6-7:160, 8-9:180, 10:200 |
| 冰箭术 | 1-9:`grade*10+130`, 10:250 |
| 冰爆术 | 1-8:`grade*10+210`, 9:300, 10:400; 仅表示被注释延迟执行器原计划使用的功率, 当前主流程不释放技能 |
| 世界末日 | 1-2:200, 3-4:250, 5-6:300, 7:350, 8:400, 9:450, 10:550; 源码中的500分支不可达 |
| 火龙枪 | 1-3:100, 4-5:200, 6:300, 7:350, 8:400, 9:450, 10:800 |

| 嗜血蛊 | `grade*10+20` |
| 一针见血 | 1-3:HP50/MP10, 4-6:HP100/MP15, 7-9:HP150/MP20, 10:HP200/MP30 |
| 附身术 | 1-4:150, 5-7:200, 8-9:250, 10:400; 源码中的300分支不可达 |

基础功率随后依次执行:

1. `_SUIT_ADDENDUM`: `hp_power += hp_power*WORKMPOWER/100.00`.
2. `_SUIT_ADDPART4`: `rand()%100<30`时再加`hp_power*WORKMPOWER2/100.00`.
3. `hp_power *= RAND(98,102)/100.0`.
4. 赋给int power, 向0截断.

目标裁剪规则: 电流术取grade个随机目标; 暴风雨取grade个; 世界末日1-2级取2个、3-4级4个、5-6级6个、7级8个、8-10级10个; 一针见血固定10个; 火星球和回旋攻击改为目标所在整排5格; 贯穿攻击按前后同列取最多2个. 随机裁剪使用RAND选择并移出原数组, 最终顺序就是被选择顺序.

##### 12.2.6.1 冰爆术当前实际行为

当前启用`_PROFESSION_ADDSKILL`, 但冰爆术不能按源码注释所描述的“两回合后爆炸”实现, 实际调用链如下:

1. 主分发遇到BATTLE_COM_S_ICE_CRACK时, 若`ice_count>=20`先把计数改为0, 然后在当前位置写`ice_use=true`、技能等级、目标、技能数组、施术者、attackNo和`ice_bout=2`.
2. 随即把施术者命令改为BATTLE_COM_NONE, 调用BATTLE_NoAction并退出本技能分支, 不调用battle_profession_attack_magic_fun.
3. BATTLE_CreateBattle中原本清空ice_count和20项队列的代码被整段注释. BattleArray只在进程启动初次分配时memset为0; 战斗槽复用时该队列不会重新初始化.
4. 回合后原本递减ice_bout并在0时调用battle_profession_attack_magic_fun的完整循环也被整段注释. 全源码没有其他启用的ice_bout执行入口.
5. 因此正常使用只产生NoAction, 队列永远不释放, 不产生攻击、状态、伤害或爆炸动画. 连续登记20次后下一次从槽0覆盖; 战斗槽复用还会继承旧ice_count.
6. dormant的PROFESSION_MAGIC_CHANG_STATUS若被测试代码直接调用, 会以`RAND(0,100)<100`判定, 实际100/101; 成功时找第一个空的10个CHAR_WORKICECRACK槽, 写倒计时3和独立MOD伤害. 第1槽到期读取CHAR_WORKMODICECRACK并可爆炸; 第2-10槽调用WorkIceCrackPlay时错误读取已减为0的倒计时槽作为伤害, 条件失败, 不爆炸.

严格8.5模式必须输出NoAction结果, 不得根据注释补出延迟爆炸. 如果未来要修复, 必须使用新的mechanics_version和显式规则开关, 不能冒充8.5兼容行为.

#### 12.2.7 职业魔法闪避和抗性伤害

职业魔法每目标先执行PROFESSION_MAGIC_DODGE. 地球一周第一阶段目标直接Miss. 玩家阈值:

`fLuck=baseLuck*3 + elementResist*0.5 + EQUITQUIMAGIC*0.4 - attackerProficiency*0.2`.

这里的`baseLuck`同样严格读取玩家`CHAR_LUCK`, 装备`ITEM_MODIFYLUCK`不参与职业魔法闪避.

非玩家阈值为`min(level*0.15,20)`, 之后同样减攻击者熟练度. `RAND(1,100)<=int(fLuck)`为Miss.

只有主判定原本命中时, 下列技能再取一次特殊门槛:

- 电流术、暴风雨: `RAND(1,100)<75`才命中, 实际为74个整数结果.
- 火龙枪、世界末日: `<90`才命中, 实际89个结果.
- 一针见血: `<50`才命中, 实际49个结果.

职业元素伤害在当前`_FIX_MAGIC_RESIST`下为:

`damage=power*(1+proficiency/100.0)*(1-resist/100.0)*(1-suit/100.0)*(1-spirit/100.0)`.

火、雷、冰分别取对应熟练度、抗性、套装槽和抗性精灵. suit还加`_EQUIT_RESIST`对应装备抗性. spirit仅在对应CHAR_MAGICFIRE、MAGICTHUNDER或MAGICICE状态大于0时取OTHERSTATUSNUMS. 结果赋int并最低限制0. 世界末日依次计算火、雷、冰三个int分量, 求和后执行`damage=int(sum/3.0)`.

`_SUIT_ADDPART4`目标的WORKUNMPOWER先从power中扣除对应百分比, 再进入上式. 电流术或召雷术命中Water附体目标时, 先用`RAND(1,100)<75`判定把power乘3, 实际触发概率为74/100.

职业魔法使用与普通攻击魔法相同的骑乘比例和同一个HP不足负剩余怪癖.

#### 12.2.8 职业特殊物理伤害

- 冰镜术: `baseDefense=CHAR_TOUGH/100`; 未骑乘取WORKDEFENCEPOWER, 骑乘取BATTLE_adjustRidePet3A防御. grade10的rate=60, 其他为`grade*5+5`. `power=120+int(defense*rate/100+(defense-baseDefense)*rate/200)`. 敌人目标上限800.
- 回旋攻击: 每个目标先把攻击者当前WORKATTACKPOWER改为`int(oldAttack*(50+grade)/100)`, 再独立物理暴击或闪避/普通伤害. 函数没有在目标间恢复oldAttack, 因而整排多目标会逐目标累计缩小攻击力, Miss也不恢复; 动作结束的统一属性恢复另行处理.
- 贯穿攻击: grade不等于10时设置MYSKILLHIT=1、MYSKILLHIT_NUM=-70并把WORKHITRIGHT减50, 再逐目标走物理暴击或闪避/普通伤害. 前排结果乘`(grade*2+70)%`, 后排乘`(grade*2+50)%`.
- 回旋和贯穿的物理暴击条件均为`RAND(1,10000)<BATTLE_CriticalCheck`. 未暴击才做BATTLE_DuckCheck.

普通魔法、职业魔法和上述职业物理结果必须逐目标生成Damage、Heal、Status、Reaction、Field或Lifecycle效果. CombatMagicDamageFormulaTrace、CombatProfessionMagicFormulaTrace和CombatRecoveryFormulaTrace保存服务端中间值. 客户端只使用skill_id选择资源, 不从option重算功能.

### 12.4 捕获

资格:

- 目标必须是敌方并带CHAR_WORK_PETFLG.
- 默认要求攻方等级+5>=目标等级.
- 特权标志可绕过等级限制.
- 宠物栏必须有空间.
- 特定目标要求背包存在配置物品.

公式:

- Df_HpPer=10-(currentHP*currentHP)/maxHP. 保留源码量纲怪癖.
- levelDiff=attackerLevel/2-defenderLevel/2.
- dexDiff=attackerDex/15-defenderDex/15.
- WorkGet=(Df_HpPer+levelDiff+dexDiff+targetCaptureBase+attackerEffectiveLuck)*charm/50. `attackerEffectiveLuck`为捕获者CHAR_WORKFIXLUCK.
- WorkGet+=MODCAPTURE.
- 目标睡眠时+15.
- 只限制最大99, 源码无统一最小下限.
- 成功条件RAND(1,100)<WorkGet.

成功后:

- 仅成功时删除对应全部捕获前置物品.
- 创建玩家宠物并写入持久化.
- 目标离场.
- 清理捕获目标AI和战斗状态.
- 生成Capture、InventoryChange、UnitLeave和奖励宠物数据.

### 12.5 逃跑

PVP的BATTLE_EscapeCheck直接成功, DP等后续规则单独处理.

PVE使用逃跑者的有效运气CHAR_WORKFIXLUCK:

- 每次尝试先把escape计数加1.
- 敌方平均等级计算中ABIO单位按-100后再加等级.
- 无敌方单位时敌方平均值为100.
- 运气5: Esc=95*attempt.
- 运气4: Esc=60*attempt-2*(enemyAvg-myLevel).
- 运气3: Esc=50*attempt-2*(enemyAvg-myLevel).
- 运气2: Esc=40*attempt-2*(enemyAvg-myLevel).
- 运气1: Esc=30*attempt-2*(enemyAvg-myLevel).
- 其他: Esc=95.
- Esc最低1, 源码不限制最大值.
- 成功条件RAND(1,100)<Esc.

### 12.7 宠物忠诚

BATTLE_PetLoyalCheck只处理存活宠物. 原动作是Wait或BATTLE_CanMoveCheck失败时不检查. 检查前清除AIBAD, 然后取`roll=RAND(1,100)`和CHAR_WORKFIXAI:

| FIXAI范围 | 8.5动作改写 |
|---|---|
| >=80 | 100%保持原动作 |
| 70-79 | `roll<10`随机目标, 实际9%; 否则保持 |
| 60-69 | `roll<20`随机目标, 实际19%; 否则保持 |
| 50-59 | `roll<35`随机目标, 实际34%; 否则保持 |
| 40-49 | `roll<50`随机目标, 实际49%; 否则保持 |
| 30-39 | `roll<70`随机技能, 实际69%; 否则保持 |
| 20-29 | `roll<70`随机技能, 实际69%; 否则保持 |
| 10-19 | `roll<80`攻击主人, 实际79%; 否则攻击敌人21% |

#### 13.2.1 专用宠物技能的源码级规则

本节补充无法只靠技能名称还原的处理器. 配置ID、名称、function、option、目标范围和原描述仍以战斗.proto的LegacyConfiguredPetSkillId为准. 实现时必须先用function映射到LegacyPetSkillHandler, 再应用本节和枚举注释, 不能把配置描述当作数值规则.

共同约束:

- `RAND(a,b)`按闭区间理解, `rand()%100`为0到99. 因此`RAND(1,100)<80`是79%, `rand()%100<15`是15%, `rand()%100<=10`是11%.
- option中的攻%、防%、敏%通常是`FIX+int(FIX*百分比/100)`. 每个处理器是否遗漏除100、把减法写成乘法或使用错误基数, 以其专用条目为准.
- 进入普通物理管线的技能复用第7到10节的命中、暴击、伤害、光镜守、死亡、击飞和动作末尾反击链. 直接改HP/MP的技能不会自动获得这些判定.
- 所有直接HP变化、宠物离场、装备删除和变身也必须输出CombatEffect及UnitStateDelta. 不能因为旧协议只有一段字符串而省略权威差量.

##### 13.2.1.1 连击、姿态和保护

| 处理器 | 8.5精确行为 |
|---|---|
| ContinuationAttack | option段数不在1到10时改1. 主循环令`attack_max=段数`,`gDamageDiv=段数`. 每段完整重算命中和暴击, 整个动作结束后共用最多5次反击链. |
| AttackCrazed | 固定攻击80%、防御70%, option直接作为段数. 主循环只改`attack_max`, 不改`gDamageDiv`, 所以每段都是未分摊伤害. |
| AttackShoot | 段数为`RAND(option段1,option段2)`, `gDamageDiv=段数`. FIXAI>=100时, 1/300概率直接8段; 当前HP绝对值<20时另有1/50概率8段. 任一方本动作标记为AttackShoot时反击检查直接失败. |
| WildViolentAttack | 段数`RAND(3,10)`, 伤害除以段数. option可修正攻防, 避值写入全局闪避修正. |
| Mighty | option的倍数乘100存入低位, 执行时`gBattleDamageModyfy=低位*0.01`; option避值写入全局闪避修正. 如果option缺少倍数字段, 初始化的2.0没有写回低位, 实际倍率为0. |
| NoGuard | 主动阶段执行NoAction, 是一回合防守姿态而不是主动攻击. 被攻击时避%直接加到普通闪避公式. 非玩家单位可在反击公式读取击%字节修正并以该姿态发起反击. 心%被保存但当前源码从未读取. |
| Guardian | option攻%/防%按`FIX+int(FIX*p/100)`修改保护宠. 含`COM:防御`时自己进入Guard并保护所选目标; 否则保护默认主人位`petBattleNo-5`. 普通非投掷物理攻击先改向保护者, 合击和投掷跳过. |
| PowerBalance | 进入普通物理管线, option攻%和防%分别按FIX值增减当前攻击和防御. |
| GuardBreakSecond | 仍执行完整物理攻击. 目标本轮Guard时伤害乘1.3, 否则乘0.7. |
| Gyrate | 取所选目标所在的5格单排, 对其中每个存活单位逐个调用完整`BATTLE_Attack`. option攻%的局部基数初始化为0, 所以源码实际不增加攻击. |

Guardian保护关系和光镜守互不替代. 先确定忠犬实际承伤者, 再读取该承伤者自己的反应槽. `CombatTargetResolutionDetail`记录声明目标、保护者和最终目标, 不能只在Damage里替换target.

##### 13.2.1.2 诱拐、偷窃、吼退和怯战

Abduct只允许敌人或宠物施术, 玩家不能施术, 玩家也不能成为目标:

1. 普通目标的`per=int((目标等级-施术者等级)*0.6+30)`, 再取`max(per,50)`, 不设上限.
2. option为正整数且目标是宠物时, 若目标FIXAI<option则`per=200`, 否则`per=0`.
3. 战斗设置了WinFunc时强制`per=0`.
4. 成功条件为`RAND(1,100)<per`. 因此普通下限50实际是49%, per>=101必成.
5. 成功时宠物目标被收回并清主人DEFAULTPET, 敌人目标直接离场.
6. 施术宠物或敌人无论成功失败都在判定后离场. 这不是捕获并创建新宠物.

Steal只对玩家目标设置`per=50`, 实际49%. 第一次成功后再以`RAND(1,100)<50`选择49%的石币分支, 否则进入51%的道具分支:

- 石币量为`int(目标当前石币*RAND(8,12)*0.01)`, 从目标扣除, 但源码没有加给施术者.
- 道具从目标背包非装备区域随机选择, 从背包移除后直接`ITEM_endExistItemsOne`, 同样没有转移给施术者.
- 实际扣到正数石币或找到道具才算成功. 成功时施术者离场; 失败不离场.

StealMoney只允许有有效主人的宠物施放:

- 敌方玩家的`per=(((50+目标等级)/4)+10)>>1`, 整数逐步截断. 敌人的`per=5`. 同边玩家为0.
- 成功条件同样严格小于. 玩家目标偷`int(当前石币*RAND(1,15)*0.01)`, 敌人目标产生`RAND(10,100)`.
- 所得加给主人并按持有上限截断. 成功后宠物离场.

Roar不造成伤害. 它把目标解析为玩家ID -1、宠物PETID或敌人PETID. 目标不能是自己. 只有PETID出现在option的竖线列表时才让目标离场; 宠物目标同时清主人DEFAULTPET. 当前大吼配置的允许列表为901、902、903、904、1056、1057、1058、1059.

BattleTimid先以攻击70%、防御40%、敏捷80%进行物理攻击. 伤害大于1后, `rand()%100<15`令目标离场; 宠物清主人DEFAULTPET, 玩家离场并解散队伍. BattleTimidSecond从option解析正负攻防敏和命%: 正号是`FIX+FIX*p/100`, 负号分支实际错误写成`FIX*p/100`, 不是减去p%; 伤害大于1后按`rand()%100<命值`判定, 只收回宠物目标.

##### 13.2.1.3 闪避术和魔法宠增益

SetDuck要求目标就是施术者. option格式为`turn|power`:

- 已有MYSKILLDUCK时仍返回成功和播放效果, 但不覆盖turn或power.
- 首次写入MYSKILLDUCK=turn、MYSKILLDUCKPOWER=power.
- 普通闪避入口优先执行`rand()%100<=power`; 命中该条件就直接返回闪避, 所以power=10实际11%, power=90实际91%.
- 每次该单位进入行动前状态序列时turn减1, 到0只输出客户端负向属性差量.
- 施放SetDuck还把CHAR_MAGICPETMP重置为0.

SetMagicPet的option格式为`turn|power|HP/STR/TGH/DEX`:

- HP分支立即以固定power调用BATTLE_MultiRecovery, turn不参与治疗.
- 属性分支先展开目标列表. 目标只要已经存在Duck、STR、TGH、DEX任一槽就跳过, 所以四种槽彼此互斥且同类型不覆盖、不刷新.
- STR、TGH、DEX分别记录独立turn和power, 行动前递减, 到0输出取消显示.
- 处理器检查`CHAR_MAGICPETMP>=3`会拒绝, 但随后只把原值写回, 全源码没有递增点. 因而8.5实际没有单场3次上限.
- 施法分支没有调用CHAR_complianceParameter, 所以服务端当前攻防敏不会在施放瞬间重算. 若之后因装备等事件触发重算, Other_DefcharWorkInt又把STR和DEX增量错误地也建立在FIXTOUGH上: `STR=FIXSTR+int(FIXTOUGH*p/100)`,`TGH=FIXTOUGH+int(FIXTOUGH*p/100)`,`DEX=FIXDEX+int(FIXTOUGH*p/100)`. 到期同样不主动重算. 严格兼容模式必须保留这些时序和错误基数.

##### 13.2.1.4 吸血、MP伤害、啮齿和属性技能

DamageToHP的option为`攻击降低百分比|吸血百分比`. 提交时攻击变为`FIXSTR-int(FIXSTR*段1/100)`. 物理伤害结算后, 仅当总伤害大于0且目标没有光镜守反应时, 恢复`int((人物伤害+骑宠伤害)*段2/100)`, 再按自身最大HP截断.

DamageToHPSecond直接把整个option当吸血百分比, 不做提交时降攻. 其攻击前还临时设置`攻击=FIXSTR+int(FIXSTR*0.2)`,`敏捷=FIXDEX+int(FIXDEX*0.2)`, 并令`perCri=perCri+int(perCri*0.3)`. 吸血仍在目标有光镜守时失效.

MPDamage的提交代码使用`def=(float)(atoi(段1)/100)`, 除法在转float前已经是整数除法, 所以配置小于100时攻击不降低. 命中后只处理玩家目标, 敌人和宠物直接跳过. 无光镜守、伤害大于0且目标MP>0时扣`int(目标当前MP*段2/100)`.

ToothCrush的HP伤害仍是普通物理伤害. 若目标是玩家, 它以50%从身体槽开始、17%头部、17%饰品1、16%饰品2选择起点, 再循环寻找第一件有效且非武器装备. 令`ratio=当前耐久/最大耐久`:

- ratio>=1: 新耐久为最大耐久的70%.
- ratio>=0.5: 新耐久为30%.
- ratio>=0.3: 新耐久为10%.
- ratio<0.3: 新耐久为0并删除装备.

ModifyAttack的option为`EA/WA/FI/WI|basePercent`. 目标对应属性大于0时, `factor=basePercent/100+(rand()%(目标属性+5))/100`, 再追加`int(原伤害*factor)`. `ALL`虽然出现在局部表中, 循环只遍历前4项, 实际不会生效.

ModifyAttackElement把本次攻击者四属性全部清0, 再按EA、WA、FI、WI索引把指定值写入一个属性, 无属性写0. BattleProperty则把目标属性旋转成攻击者临时属性: 攻地=目标水、攻水=目标火、攻火=目标风、攻风=目标地, 无属性为`100-目标四属性总和`; 注册效果持续到战斗清理CHAR_BATTLEPROPERTY.

##### 13.2.1.5 特殊目标、追击、变身和直接伤害

Sonic先对所选目标执行完整物理攻击. 若目标槽是5到9或15到19, 再对`target-5`执行第二次完整攻击. 第二击独立判定命中、暴击和光镜守, 最终伤害乘0.5. 所选目标不是后排宠物位时没有第二击.

Regret使用相同的后排到主人贯穿目标规则. 主目标为完整伤害, 第二目标伤害乘0.8. 每个目标在自己的伤害事件中以option命%作为PROFESSION_BATTLE_StatusAttackCheck的基础值判定Dizzy, 成功写2并清空该目标动作.

Retrace先执行一次普通攻击. 只有返回值严格等于DODGE时才执行`RAND(1,100)<80`, 即实际79%. 成功则把攻击设为`FIXSTR+int(FIXSTR*0.2)`并对同一目标再执行一次完整普通攻击. MISS、ALLGUARD、ARRANGE、光镜守均不会触发追击.

Hector在普通攻击前先以`PROFESSION_BATTLE_StatusAttackCheck(Paralysis,60)`判定, 成功直接写麻痹1回合. case没有break, 随后贯穿普通物理攻击分支. 因而状态先于伤害和死亡结算.

FallGround先走完整物理攻击. 只有伤害大于0、没有光镜守且不是同队时才掷`RAND(0,100)>50+装备落马抗性`. 无抗性时是50/101. 玩家只有当前RIDE PET>=0才落马. 启用敌人落马分支时, 敌人落马还把基础STR、TOUGH、VITAL各乘0.7并重算属性.

BecomeFox要求普通攻击结果不是MISS、DODGE、ALLGUARD、ARRANGE, 目标仍存活, 目标不是玩家且WORK_PETFLG非0. 再以`rand()%100<31`判定. 成功后写FOXROUND=当前战斗回合、形象101749并强制落马. 变身期间只能Attack、Guard或None, 强制徒手, 每次动作前攻防敏取FIX值的80%. 当`当前回合-施加回合>2`时恢复.

BecomePig要求相同的物理命中结果、存活敌方玩家和不同队. 源码写成`pszOption=="\\0"`的指针比较, 正常非空配置进入else, 固定使用成功率100、60秒、形象100250. 成功条件`rand()%100<100`必成. 首次写60秒, 再次命中在剩余值上累加60; 同时清道具/NPC/狐狸变身并强制落马. 乌力期间强制徒手, 允许攻击、防御、待机、道具、逃跑、捕获和宠物进出, 其他动作改为Guard.

ShowMercy在BATTLE_DamageSub前检查. 若普通伤害足以令目标HP降到0, 把本次伤害改为`目标当前HP-1`; 骑乘伤害分配仍按随后流程处理, 客户端必须采用最终DamageDelta而不是自行截断.

FireKill先修正死亡、无效或地球一周目标, 禁止同队. 物理部分把攻击设为FIXSTR的80%, 使用专用BATTLE_Attack_FIREKILL, 然后追加火属性2、power=200的固定攻击魔法. 两部分必须是同一ActionInstance下有顺序的子事件.

##### 13.2.1.6 雷尔技能和通用战斗模型

BatFly忽略所选单体, 对敌方展开列表直接改HP, 不执行普通命中、暴击、反击或光镜守:

- 无存活骑宠: 人物扣`floor(当前HP/10)`. 商为0时仍扣1.
- 有存活骑宠: 人物和骑宠各扣`floor(各自当前HP/20)`. 任一商为0仍各扣1, 骑宠到0则落马.
- 所有扣血相加为施术者治疗量. 若`施术者当前HP+总量>最大HP`, 源码把HP设为最大值后又把上报治疗量改成0. 状态实际增量与旧显示量因此可能不同.

DivideAttack同样直接处理敌方全体:

1. 先让每个玩家目标MP变为`MP-floor(MP/2)`, 即保留向上取整的一半.
2. 无存活骑宠时人物扣`floor(当前HP/5)`, 商为0仍扣1.
3. 有存活骑宠时人物和骑宠各扣`floor(各自当前HP/10)`, 商为0仍各扣1, 骑宠到0落马.
4. 不治疗施术者, 不走命中、暴击、光镜守、反击和普通DefineAttack死亡表现. 现代实现仍必须在直接扣到0后产生Death/胜负检查.

BattleModel的option七段依次为`type|objectCount|status|turn|statusBaseRate|attributeChange|actionImages`:

- objectCount<=0时随机1到10, >10截为10. actionImages最多4个, 按攻击物件循环使用; 没有图号则NoAction.
- type位0为1且攻击物件少于目标数时, 复用物件覆盖全部目标; 位0为0时只攻击前objectCount个目标. 物件多于等于目标数时先每目标一次, 剩余物件随机重复目标.
- type位2为1表示物理承伤, 会应用忠犬、光镜守及骑乘分配; 为0时仍调用AttackSeq取得命中/暴击, 但DamageSub以react=-1走非物理直扣分支.
- 每个物件独立调用AttackSeq. 命中并造成正伤害后可按配置状态、回合和基础率调用BATTLE_StatusAttackCheck. 麻痹、睡眠、石化、魔障成功时清目标动作.
- attributeChange在提交阶段解析攻、防、敏. 带%时在当前值上加`int(当前值*p/100)`, 不带%时直接把属性设为该数字.

##### 13.2.1.7 源码缺陷的兼容原则

本节列出的未递增计数、错误整数除法、指针比较、错误属性基数、缺少重算和显示量不一致均属于8.5机制的一部分. 严格兼容实现不得静默修复. 如果未来要修正, 必须启用新的CombatRuleSnapshot规则版本并增加显式开关; 同一场战斗内不允许混用修正版和8.5版.

### 13.3 pet.skill.8.0.yaml迁移规则

原YAML的名称、描述、function、option、free、kind、field、target、use_type、cost和code已经进入战斗.proto配置枚举注释. YAML只有388条记录, 最终目录补齐8.5/基础配置后为394条.

发生冲突时:

- 功能行为以8.5注册表和处理器源码为准.
- 8.0文本仅作为名称和历史描述.
- 重复ID不丢弃, 枚举名使用ID和源行号区分.
- _PETSKILL_OPTIMUM或_MAGIC_OPTIMUM后出现记录覆盖前记录的行为必须记录.
- MAGIC_AttSkill等配置存在但注册行被注释的函数标为Unregistered, 不得假装可执行.
- ENEMYSKILL_EnemyHELP和ENEMYSKILL_EnemyHelp大小写不一致按strcmp失败处理.

### 13.4 战斗类型和旧状态机

8.5战斗类型完整集合已经进入CombatBattleType:

- PlayerVsEnemy.
- PlayerVsPlayer.
- EnemyVsEnemy.

4. 冻结胜负和奖励.

### 13.5 观战和求援

观战:

- 8.5通过BATTLE_TYPE_WATCH房间和pNext/pBefore链链接主战斗.
- 观战者收到主战斗初始快照和每回合同一动作脚本.
- 现代实现不创建第二份战斗运行态. 观战者订阅同一CombatRoom结果, CombatBattleStart.observer=true.
- 观战者没有可控unit_key, 不能提交CombatRoundActionReq.
- 观战者加入时收到当前完整单位/场地状态, 此后收到与参战者同sequence的CombatRoundResultNotify.
- 观战者慢客户端不得阻塞主战斗回合. 8.5曾让WatchMovie状态影响回合推进, 现代Actor架构不保留该网络耦合.

求援:

- 8.5的HL_RECV切换BSIDE_FLG_HELP_OK, HL_SEND同步本侧人物.
- 救援者通过BATTLE_RescueTry进入已有战斗, 模式为BATTLE_CHARMODE_RESCUE.
- 现代实现必须把求援开关作为房间权威状态, 身份和地图条件由服务端校验.
- 救援成功生成UnitEnter事件、完整CombatUnit/CombatUnitState和LegacyOperationalState_Rescue.
- Rescue单位不应仅凭存在维持阵营有效存活, 是否转为普通战斗单位严格按8.5救援处理完成点.
- 求援和观战属于附加入口, 不改变正常Start->Action->Result->FlowComplete回合状态机.

## 14. 有效存活和最终胜负

### 14.1 有效存活定义

发起方或防守方有效存活单位按战斗类型计算:

- 玩家角色存活时计入.
- 玩家宠物不计入, 即使宠物仍有HP.
- PVE敌方怪物计入.
- PVE敌方NPC计入.
- Rescue、已离场、已捕获、已逃跑和死亡单位不计入.
- 临时召唤物是否计入必须由其8.5来源规则明确, 默认不替代玩家角色.

### 14.2 检查时点

每个单位动作及全部必要后处理完成后检查. 不在以下中间点提前结算:

- 多段攻击某一段伤害刚扣除.
- 镜伤害尚未处理.
- 陷阱或针刺反伤尚未处理.
- 反击链尚未结束.
- 攻击者尚未返回原位并完成倒地状态.

合击的每个成员独立计算并生成表现, 但整组合击及必要后处理完成后才检查有效存活. 普通累计伤害在最后成员统一扣除; 成员级伤害反应造成死亡时按8.5局部条件停止后续成员.

### 14.3 同时为0

同一原子边界双方有效存活数都为0时:

- 不定义平局.
- 发起方判负.
- 防守方胜利.
- CombatBattleEndReason取DefenderWin.

### 14.4 结算顺序

1. 冻结停止点状态和事件.
2. 确定唯一winner_camp和end_reason.
3. 计算经验、DP、掉落、捕获宠物和脚本回调.
4. 持久化奖励和资源变化.
5. 构造最终CombatRoundResultNotify.
6. Account清除匹配CombatRoom引用.
7. 向Gateway发送最终结果.
8. CombatRoom从管理器移除并停止Actor.

奖励持久化一旦开始, 后续失败必须显式回滚、补偿或暴露错误, 不得发送伪成功结果.

### 14.5 8.5结束清理等价行为

BATTLE_Finish和BATTLE_Exit的行为必须在现代Account/CombatRoom边界中得到等价处理:

- PVE胜利且存在WinFunc时执行NPC或特殊战斗胜利回调.
- PVP、DP、家族PK和AutoPK按当前启用宏计算点数、传送和额外状态.
- 对每个参战单位结算经验、金钱、DP和战利品.
- 清除战斗索引、战斗模式、命令和临时Entry引用.
- 玩家战败退出时按8.5规则保证场外HP至少为1.
- 清除普通异常、MagicTbl、光镜守、变身、骑乘临时状态和沉默UI状态.
- 清理所有宠物战斗状态并同步宠物HP和出战选择.
- PVP关闭duel标志.
- 同步角色flags、位置、方向和队伍HP.
- 观战者退出订阅, 不参与奖励.
- 最终删除房间和所有临时怪物/NPC运行态.

旧服可能在BATTLE_Finish内直接执行多种外部副作用. 现代实现应先完成本地胜负和奖励纯计算, 再按持久化事务/补偿流程执行Account和外部服务写入.

## 15. 客户端事件和表现

### 15.1 单一事件/效果流

- CombatEvent.sequence是回合全局逻辑顺序.
- parent_event_id和root_event_id表达反击、被动和状态触发链.
- CombatEffect.sequence是事件内顺序.
- 每个效果同时携带表现语义和CombatUnitStateDelta.
- 客户端按事件和效果顺序播放并应用差量.
- 回合末CombatUnitState是纠偏快照, 不是让客户端重算事件.

### 15.2 必须结构化表达的效果

- ApproachTarget和ReturnHome.
- 普通受击、Critical、Miss、Dodge、Guard、Arrange.
- Protect忠犬改向.
- Absorb、Reflect、Vanish、Trap、Acupuncture.
- Damage、Heal、MP和其他AssetChange.
- Status Add、Update、Remove、Expire、Tick、Resist、Immune和组冲突.
- Knockback、Knockdown、FallMount、Death、Revive.
- UnitEnter、UnitLeave、Escape、Capture、Transform.
- InventoryChange、EquipmentChange、FieldChange.

animation_id、visual_effect_id和sound_id可为0, 由客户端按action_id、effect_kind和本地资源表选择. 服务端负责顺序和最终姿态, 不负责像素坐标和动画时长.

### 15.3 一般、暴击、反击和反击的反击

每次攻击段的CombatHitTargetResult同时提供:

- Normal、Critical、Miss、Dodge、Guard等组合标志.
- original_target和actual_target.
- raw_damage和final_damage.
- HP before/after.
- 光镜守反应和次数before/after.
- 骑乘、忠犬、反伤的damage_allocation_list.
- legacy BATTLE_RET和BCF位图, 仅用于调试.

反击和反击的反击不是新的伤害类型公式, 而是独立Counter事件. counter_depth从1递增, 每次重新执行反击资格、概率、AttackSeq、0.75倍率和伤害反应.

## 16. 可复现测试向量

以下向量用于防止实现把公式、比较符或原子边界改错. 测试应通过可注入确定性随机流精确给出每次draw.

### 16.1 基础物伤

输入attack=160, defense=100, 无元素和其他修正.

- attack>=defense*8/7.
- RAND(0,attack/8)=RAND(0,20)固定返回8.
- K0=8-160/16=8-10=-2.
- damage=(160-100)*2.0-2=118.

期望base_damage=118.

### 16.2 Guard截断

承接damage=118, Guard roll=96.

- 倍率50%.
- int复合赋值结果59.

期望after_guard=59.

### 16.3 骑乘分摊怪癖

输入damage=100, charDefense=60, petDefense=40.

- playerDamage=(100*40)/(60+40)+1=41.
- petDamage=100-41+1=60.
- 合计101.

期望协议分别记录41和60, 不能强行修正为总和100.

### 16.4 状态冲突

目标已有Stone remaining_round=5, 请求Sleep remaining_round=3.

- 不抽状态成功率随机值.
- apply_result=RejectedGroupOccupied.
- resulting_status仍为Stone 5.
- 可以已经播放状态魔法视觉效果.

### 16.5 光镜守优先级

目标同时有Vanish=1、Absorb=2、Reflect=3.

- 第一段选择Vanish, 变为0, Absorb和Reflect不变.
- 第二段选择Absorb, 变为1.
- 第三段选择Absorb, 变为0.
- 第四段选择Reflect, 变为2.

### 16.6 三段和十段反击

让每次反击判定都成功, 双方始终存活.

- 三段主动攻击后最多生成5个Counter事件.
- 十段主动攻击后最多生成5个Counter事件.
- 两者都不是段数乘5.

### 16.7 合击不可闪避

两个成员成立合击, 目标闪避率即使达到75%:

- 不生成Dodge随机抽取.
- dodge_check_bypassed=true.
- 两成员分别计算Critical和Reaction.

### 16.8 反击击倒回原位

A ApproachTarget到B面前, B反击令A死亡.

期望A相关效果顺序:

1. 反击Damage.
2. ReturnHome.
3. Knockdown或Death, 位置为A home_position.

### 16.9 双方同时为0

一个完整动作后处理结束时双方有效存活都为0.

- 立即结束.
- winner_camp=Defender.
- end_reason=DefenderWin.
- 不产生Draw.

## 18. 实现验收清单

实现完成必须同时满足:

- 只由服务端计算全部战斗结果.
- 现有Actor、Gateway、Online和CombatUnitKey边界保持不变.
- CombatBattleStartNotify到CombatFlowComplete完整可运行.
- 普通攻击、武器目标、多段、暴击、反击链、合击和击倒表现都有测试.
- 三段和十段共享最多5次反击.
- 合击不闪避, 不触发忠犬, 但逐成员触发光镜守.
- 三类状态协议完整, 所有BATTLE_ST、BATTLE_MST、BATTLE_MD和运行标志可表示.
- 状态互斥、重施覆盖、触发消耗和跳数时点与8.5一致.
- 物伤、暴击、闪避、反击、元素、Guard、骑乘、捕获和逃跑有固定随机向量测试.
- 普通攻击魔法的TrueMagic共用随机、逐目标闪避、魔抗、元素矩阵、0.7失败倍率和骑乘分配有固定随机向量测试.
- 职业魔法的等级边界、不可达功率分支、98%-102%浮动、特殊二次命中、抗性乘法和Doom三元素平均有固定向量测试.
- 恢复和复活覆盖_MAGIC_REHPAI缺血分配、百分号被忽略/覆盖、power=0回满及PVP玩家不可复活.
- 战斗道具17个处理器的效果、耐久和消费时点全部有测试.
- 每个int截断点和每个<或<=有回归测试.
- 基础运气、装备修正合计和有效运气分别有快照测试; 所有读取点都有BaseLuck/EffectiveLuck来源断言.

- 玩家宠物不维持玩家阵营, PVE怪物/NPC维持敌方阵营.

- 客户端只消费一个CombatEvent/CombatEffect流.

- 角色和宠物分别提交动作; 超时未提交的角色和宠物都直接防御, 主动待机仅由宠物明确提交.
