# 石器时代8.5战斗状态覆盖矩阵

本文档主矩阵覆盖8.5实际编译分支中的`BATTLE_ST_*`普通/职业状态, 并在独立章节记录当前已接入的`BATTLE_MST_*`魔法状态. 两组状态使用不同工作槽和生命周期, 不合并计数. `BATTLE_MD_*`受击反应和其他独立工作槽仍不计入本矩阵.

源码基准固定为`D:\石器资源\石器时代8.5的服务端源码LINUX下开发\85`.

## 1. 精确统计

- `gmsv/include/battle_event.h:91-146`定义44个状态枚举值, 即`BATTLE_ST_NONE=0`至`BATTLE_ST_ICECRACK10=43`.
- `BATTLE_ST_END=44`是数组上界哨兵, 不是可施加状态.
- 因此可传入状态判定的正状态码为43个, 即`1..43`.
- 当前`_PET_SKILL_SARS`、`_PROFESSION_SKILL`和`_PROFESSION_ADDSKILL`均已定义, 0..43没有因条件编译而形成编号空洞.
- 43个正状态码中, 30个存在当前启用主流程可达的存储生产者, 12个只有保留槽或被当前分发阻断的生产者, 1个是只用于请求的虚拟状态码31.

分类结果:

| 分类 | 数量 | 状态码 |
|---|---:|---|
| 当前主流程可写入的存储状态 | 30 | 1-14, 16-18, 20-23, 25-30, 32-34 |
| 当前主流程不写入的保留/失效状态 | 12 | 15, 19, 24, 35-43 |
| 只用于请求、不写入自身槽 | 1 | 31 |

## 2. 共用生命周期

### 2.1 存储映射

`gmsv/battle/battle_event.c:90-123`中的`StatusTbl[]`按状态码把`BATTLE_ST_*`映射到`CHAR_WORK*`工作槽. 状态码不是`CHAR_WORK*`字段号, 两者不得混用.

`BATTLE_ST_NONE`映射为`-1`. 只有`1..43`能作为`StatusTbl`下标参与状态存储.

### 2.2 施加冲突

矩阵中的冲突类型使用以下缩写:

| 类型 | 规则 |
|---|---|
| G | `BATTLE_StatusAttackCheck`先扫描`StatusTbl[1..43]`, 任一槽大于0即拒绝, 不覆盖、不叠加, 再执行普通成功率判定 |
| P | `PROFESSION_BATTLE_StatusAttackCheck`普通分支先消费一次随机数, 再扫描`StatusTbl[1..43]`, 任一槽大于0即拒绝 |
| X | 直接写工作槽, 绕过全局互斥. 是否覆盖或并存由该写入点决定 |
| V | 虚拟请求码. 不写入该状态自身的`StatusTbl`槽 |
| - | 当前启用主流程没有生产者 |

G/P是主要规则, 但不是全局不变量. 当前源码至少存在3类绕过路径:

- SARS传播只检查目标是否已有SARS, 可与目标已有的其他状态并存.
- 丢栗子命中后直接写`CHAR_WORKSLEEP=3`, 可绕过普通状态互斥.
- 世界末日的恐惧直接写`CHAR_WORKFEAR=4`, 可与其他状态并存并覆盖旧恐惧剩余值.

当前现代PVE已实现`9000016`首次SARS的通用互斥检查, 以及传播时只拒绝已有SARS的绕过规则. 传播可与Sleep并存, 行动前按状态号先处理Sleep再处理SARS. 玩家MP、骑宠毒伤和其他普通状态槽尚未接入, 因而本矩阵仍不能视为完整状态系统验收.

### 2.3 行动前结算

`BATTLE_StatusSeq`在每个存活单位执行主动动作前运行, 顺序如下:

1. 先用动作开始时的状态调用`BATTLE_CanMoveCheck`. 不能行动时把当前命令改为`BATTLE_COM_NONE`.
2. 按状态码1..43递增顺序处理所有正值槽.
3. 每个槽先执行`--cnt`, 再处理到期和状态效果.
4. `BATTLE_StatusSeq`返回后再次调用`BATTLE_CanMoveCheck`, 但此前被清掉的命令不会恢复.

当前现代服务器已接入AttackShoot`9000013/9000046`、Combined普通睡眠魔法和BattleModel`9000048/9000066/9000111`三类Sleep生产路径, 仍不是完整通用状态系统. 两版栗子每段正伤害先清除目标已有Sleep, 再以20%覆盖为3次行动; Combined按对应magic的基础率和计数结算; BattleModel在正伤害、目标存活且无其他普通状态时按8.5阈值判定, 649/668写3, 714海盗分身术写2. 三条路径命中睡眠都会立即取消目标本回合尚未执行的原技能. 睡眠单位轮到行动时递减剩余次数, 被取消的原动作不进入协议; 从1递减到0时通过Status效果通知客户端移除状态. 后续正伤害可以提前唤醒, 但不会恢复已经跳过的本回合动作.

当前现代服务器还把BattleModel`9000052/9000067/9000112/9000162`作为石化生产路径. 654同名肆无忌蛋、669朱雀之怒和1039 T朱雀之怒成功写Stone=3, 715影分身之术写Stone=2; 四者都只在正伤害、目标存活且无其他普通状态时按基础30、等级差、攻击方幸运、石化抗性和体力占比判定, 成功立即清除目标Guard/NoGuard和当前动作. 石化目标轮到行动时递减, 被取消的原动作不进入协议; 石化不会被伤害唤醒, 存续期间物理防御乘2. T朱雀之怒后续对象重复攻击已石化目标时会立即读取翻倍防御. 其他状态来源、免疫和完整通用`BATTLE_StatusSeq`仍待开发.

当前现代服务器接入ColumnAttack`9000039/9000064/9000115`和BattleModel`9000117/9000154/9000161`两类Dizzy生产路径. 三个ColumnAttack版本分别以基础率20、30和50严格判定, 成功写Dizzy=2并立即取消目标已提交动作和Guard/NoGuard; DODGE和0伤害仍消费状态随机, 目标死亡或已有状态时也先抽数后失败. 炎凝杀、玄武火炮和群猪齐福只在正伤害、目标存活且无普通状态时按各自BattleModel基础值30/35/30公式判定, 命中时分别写2/4/1, 但不立即清动作或姿态, 到目标真正开始行动时再由Dizzy取消动作并清Guard/NoGuard. Dizzy每次目标轮到行动递减一次, 被取消的原动作不进入协议; 最后一次只输出实际发生的Status移除效果. 群猪齐福因此只取消下一次行动.

当前现代服务器还接入BattleModel`9000136`至`9000147`作为Dragnet状态14的生产路径. 12个天罗地网术只有旧客户端图片编号不同, 服务端统一使用5个物理对象、全敌覆盖、基础成功30、攻击-4%和计数2. “罗”必须映射`BATTLE_ST_DRAGNET=14`; 状态13是尚未接入的`BATTLE_ST_ENTWINE`“缠”. Dragnet只在正伤害、目标存活且无普通状态时按BattleModel通用公式判定, 命中瞬间不清已经预激活的Guard/NoGuard; 目标真正轮到行动时才清姿态、取消动作并递减. 状态正值还会零抽数禁止普通闪避和反击. 两次被取消的原动作均不进入协议, 第二次只输出实际发生的Status移除效果. 旧守护候选对Dragnet目标的拒绝规则随忠犬/守护链保持待开发.

当前现代服务器还接入`9000070`全体沉默作为NoCast状态10的生产路径. 服务端按敌方position升序扫描全部存活单位, 已有任意普通状态的目标在随机前跳过; 其余目标以基础成功50、等级差、施术者幸运、目标体力占比和当前0点NoCast抗性计算阈值, 严格`RAND(1,100)<threshold`时写3. NoCast在目标每次行动开始按3→2→1→0递减, 到0只输出Status移除. 它不属于不可行动状态, 不取消普通攻击、防御或独立宠物技能命令. 状态递减后仍为正数时, `MAGIC_DirectUse`会静默拒绝人物咒术以及Combined、FieldAttributeChange、ElementReverse、CallDragon宠物法术; 递减到0时先输出移除并允许本次法术继续. 当前PVE尚无角色咒术action生产入口, 但现有四类宠物法术使用点已接入, 不能按“所有宠物skill都不受影响”处理.

当前现代服务器接入`9000071`全体魔障以及BattleModel`9000110`Q雷分身、`9000156`雷斯特分身和`9000159`冰凝杀作为Barrier状态9生产路径. 全体魔障按敌方整营和基础成功50判定, 配置turn 2通过`BATTLE_S_Barrier`写成3; Q雷分身和冰凝杀按每个正伤害对象及BattleModel基础30公式判定并直接写配置值2; 雷斯特分身使用基础25并直接写3. 四者命中时都取消目标当前动作并清Guard/NoGuard. 行动阶段的旧Barrier递减回写使全体魔障和雷斯特分身形成`3→2→3`, Q雷分身和冰凝杀形成`2→1→2`; 四者都不会自然到期, 只能由净化或战斗结束清除.

当前Combined状态恢复已覆盖`9000036`和`9000160`两版净化之舞及`9000047`配药. 61号全快每个目标只清除当前编号最高的一个已接入状态; 当前优先级从Dragnet 14开始, 再依次扫描Dizzy 12、SARS 11、NoCast 10、Barrier 9和其余较低状态. 旧判断把状态ID与`CHAR_WORKCONFUSION=50`比较, 因而当前编译定义下`status=0`覆盖有效状态ID 1至43, 不是只覆盖1至6. 配药先从`71/81/91/101/121/61`随机一种, 前五种指定药只有在毒/麻痹/石化/混乱/睡眠恰好是目标最高状态时才清除, 不会绕过更高状态去清较低槽. 状态恢复不会恢复此前已被状态取消的本回合动作, 也不生成Wait.

普通到期路径会输出状态解除并保留槽值0. 以下状态例外:

- Weaken和Barrier在递减后只要仍大于0就写回`cnt+1`. 初始值大于1时不会自然继续递减, 只能由恢复技能或战斗全清移除.
- IceCrack 1-10槽到0时不走普通到期`continue`, 而是进入冰爆专用分支.
- DeepPoison在剩余值到1时直接把目标HP置0并标记死亡.

### 2.4 清除路径

矩阵中的清除缩写:

| 缩写 | 清除路径 |
|---|---|
| N | `BATTLE_StatusSeq`自然递减到0 |
| R | `BATTLE_MultiStatusRecovery`指定恢复. 它先找目标当前最高状态码, 只有指定码与最高码相等时才清除 |
| R0 | 状态0/全快恢复. 仍只检查最高状态码; 旧源码用`CHAR_WORKCONFUSION`工作槽常量作上限比较, 不是状态码6. 当前已接入1..12及14均低于该工作槽值并可按最高编号清除 |
| W | 有效伤害唤醒, 清除Sleep |
| A | `BATTLE_BadStatusAllClr`在战斗进入、离开和统一清理时清除1..43全部槽 |
| S | 状态自己的专用到期/清除代码 |

`aszStatus[]`只提供0..31的配置字符串. 因此32..43不能通过现有字符串解析入口选择为指定恢复状态, 只能自然到期、专用清除或全清.

### 2.5 魔法状态BATTLE_MST

`MagicTbl[]`与普通`StatusTbl[]`相互独立. 当前启用枚举为None 0、DefMagic 1、SuperWall 2、ResistFire 3、ResistThunder 4和ResistIce 5.

`BATTLE_MultiMagicStatusChange`对每个目标先扫描整个MagicTbl组; 组内已有任意正状态即拒绝本次写入, 不覆盖、不叠加、不刷新. `BATTLE_MagicStatusSeq`在该单位每次轮到行动时、完整`BATTLE_StatusSeq`之后把每个正计数减1, 到0清除; 魔法状态自身不取消动作.

当前现代PVE只接入SuperWall:

| 状态 | 当前生产者 | 运行态和随机顺序 | 当前边界 |
|---|---|---|---|
| SuperWall 2 | `9000056`玄武铁壁`super_wall/3/50/whole_allied_camp`; `9000122`福星高照`super_wall/3/60/whole_allied_camp` | 两个ID复用同一处理器, 对己方存活整营施加3次行动; 已有铁壁保留原值. 每次物理防御先消费`rand()%20`, 增加配置基础比例至基础比例加19个百分点, 再执行敌方防御浮动、石化和Regret覆盖. 每次单位行动开始递减, 到期输出AttributeModifier(enabled=false), 不输出Wait | 当前互斥组只有SuperWall运行态; DefMagic及火/雷/冰抗、专用动画、骑乘和PVP待开发 |

施法动作本身不消费随机数. 施法回合中尚未行动的目标随后轮到行动时会立即从3减到2, 这是8.5按行动机会计数的结果, 不是按完整回合统一递减.

### 2.6 魔法宠属性槽

`PETSKILL_SetDuck`和`PETSKILL_SetMagicPet`使用`CHAR_MYSKILLDUCK/STR/TGH/DEX`独立工作槽, 不属于普通`StatusTbl`或魔法`MagicTbl`. SetMagicPet对每个目标施加属性时只要四槽任一已有正数状态就跳过, 不覆盖、不叠加、不刷新. SetDuck自身只检查Duck, 所以已有STR/TGH/DEX不会阻止首次Duck; 已有Duck却会阻止后续SetMagicPet属性强化. 这是8.5处理器调用点形成的单向占用, 不能改成对称互斥. 四槽在单位每次行动开始、普通状态和魔法状态之后递减; 到0不取消动作.

当前`9000163`端午烈炎是STR槽的新生产来源, 写入3/30且不进入NoCast的`MAGIC_DirectUse`拦截. 施加时不立即改变FIX攻击, 下一次PreCommand按`FIXSTR += FIXTOUGH*30/100`生效. 若目标在施放当回合排在施术者之后行动, 它会先把3减到2但仍使用施放前已计算的FIX攻击; 到0只移除槽位和输出AttributeModifier(enabled=false), 不取消动作、不生成Wait, 到期当回合FIX攻击保持到下一次属性重算.

当前`9000164`端午铁壁是TGH槽的新生产来源, 写入3/30且同样不进入NoCast的`MAGIC_DirectUse`拦截. 施加时不立即改变FIX防御, 下一次PreCommand按C整数公式`FIXTOUGH += FIXTOUGH*30/100`生效, 基础防御99得到128. 若目标在施放当回合排在施术者之后行动, 它先把3减到2但仍使用施放前的FIX防御; 到0只移除槽位和输出AttributeModifier(enabled=false), 不取消动作或生成占位事件, 到期当回合FIX防御保持到下一次属性重算.

当前`9000165`端午疾速是DEX槽的新生产来源, 写入3/30且同样不进入NoCast的`MAGIC_DirectUse`拦截. 施加时不立即改变FIX敏捷或当前回合已经确定的行动顺序; 下一次PreCommand按8.5错误基数和C整数公式`FIXDEX += FIXTOUGH*30/100`生效, 基础敏捷101、防御99得到130而不是131. 若目标在施放当回合排在施术者之后行动, 它先把3减到2但仍使用施放前的FIX敏捷; 到0只移除槽位和输出AttributeModifier(enabled=false), 不取消动作或生成占位事件, 到期当回合FIX敏捷保持到下一次属性重算.

当前`9000166`端午滋润不生产属性槽或普通状态. HP分支在四槽检查之前直接执行, 所以已有Duck/STR/TGH/DEX不会阻止回复, 原槽也不会被覆盖或刷新; option中的turn=3不进入运行态. 战斗Poison/DeepPoison不是8.5 `_TYPE_TOXICATION`读取的连接级账号中毒标记, 不构成禁疗.
