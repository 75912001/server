# 服务器缩容设计

本文记录 server 项目的缩容语义、待确认决策和后续改造方向。当前阶段只讨论设计, 不改代码。

## 已确认上下文

- 扩容设计已经约束: 扩容只接新流量, 不迁移已有 TCP 连接或 online actor。
- gateway 持有客户端 TCP 连接和本地 `Account` actor。
- online 持有账号业务 actor。
- login 通过外部 LB/网关接收 HTTP 新请求, server 内部不让客户端发现 login。
- cache 是无状态 Redis 访问层, 服务实例本身不保存账号在线状态。
- login 通过 etcd 发现 gateway/cache, gateway 通过 etcd 发现 online/cache/gateway peer, online 通过 etcd 发现 cache。
- login 和 gateway 当前按本地 `availableLoad` 选择目标实例, etcd update 会覆盖本地估算值。
- etcd del 事件会让调用方移除对应实例并关闭本地 gRPC 连接。

## 待确认问题

### 1. 缩容是否允许主动断开在线账号

缩容首先需要确认目标语义: 是只做摘流并等待自然排空, 还是允许在超时后主动断开仍在线的账号。

推荐决策:

- gateway/online 采用两阶段缩容: 先摘流, 不再接新账号; 再等待已有连接和 actor 自然下线。
- 为了避免缩容永远卡住, 支持可配置超时后的强制下线。
- 第一版可以只实现摘流和可观测排空状态, 强制下线作为明确运维动作, 不自动默认执行。
