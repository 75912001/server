# 共享游戏配置

本目录是 server 和 sa.desktop 共享游戏配置的唯一源头.

当前共享文件:

- `character.yaml`: 角色资源配置.
- `character.sprite.yaml`: 角色动画帧配置, 按动画序号保存方向、动作和帧 ID.
- `character.skill.yaml`: 角色技能配置.
- `enemy.group.yaml`: 敌人组配置.
- `enemy.exp.yaml`: 敌人等级基础经验配置.
- `exp.yaml`: 经验等级配置.
- `item.yaml`: 可堆叠道具及其固定 EXP 使用效果配置.
- `offset.yaml`: 帧资源图片偏移配置, 使用唯一 `frameid` 映射 `[offsetX,offsetY]`.
- `pet.skill.yaml`: 宠物技能配置.
- `pet.sprite.yaml`: 宠物动画帧配置, 按动画序号保存方向、动作和帧 ID.
- `pet.yaml`: 宠物主体配置.
- `scene.yaml`: 场景配置, 维护场景可遇敌敌人组和权重.

`pet.yaml` 的 `pet` 段使用 `pet.<family>: [...]` 按宠物系别归类, 方便直接查看同系宠物; server 加载时校验 family 名称和列表非空, 随后展平并继续按宠物 ID 建立业务索引, 不保存运行时 family 字段. 文件顶部注释形式的 `petFamilies` 仅作为新增系别时的复制模板, 不参与 YAML 解析.

`character.yaml` 每个角色的 ID 使用 `1000000 + sprite.unarmed` 计算, `sprite` 按 `unarmed`、`axe`、`stick`、`spear`、`bow` 保存动作配置 ID, 引用 `character.sprite.yaml` 中相同的 `sprite[].id`; `character.sprite.yaml` 保存完整的八方向、动作和帧 ID, 当前不由 server 业务逻辑消费.

`pet.yaml` 每只宠物的 `sprite` 保存动画序号, 引用 `pet.sprite.yaml` 中相同 `sprite[].id`; `pet.sprite.yaml` 保存完整的方向、动作和帧 ID, 当前不由 server 业务逻辑消费.

`pet.sprite.yaml` 中的 `action7` 仅按资源原始序号保留第七组帧. 由于不同宠物的该组帧可能表现为攻击、防御或其他动作, 当前不赋予统一业务语义; server 不消费该字段, sa.desktop 读取配置时也直接跳过, 不校验、不缓存且不提供播放入口.

`item.yaml` 按道具 ID 保存名称、sprite、堆叠上限和使用效果. `sprite` 必须明确配置, `0` 表示尚无图像资源且客户端仅显示名称; `use.target` 仅允许 `pet` 或 `character`, `use.exp` 必须大于 0. 宠物修炼丹使用 `3000001-3000099` 区间, 角色修炼丹使用 `3000101-3000199` 区间; 当前两类都配置小、中、大三档, 分别固定增加 1000 万、5000 万和 1 亿 EXP.

server 只校验 YAML 自身结构, 服务端消费字段, 枚举, 数值范围和跨配置引用. 其中 `character.yaml` 在 server 侧只消费并校验 `id` 和 `isRole`; `character.skill.yaml`提供角色技能ID、名称和说明, 当前战斗入口开放攻击、防御和逃离; `scene.yaml` 用于 online 根据角色当前场景按权重选择敌人组, 并校验 `enemyGroups[].id` 必须存在于 `enemy.group.yaml`; `enemy.group.yaml` 用于生成敌人模板, 数量和等级; `enemy.exp.yaml` 提供敌人生成时按等级查询的基础 EXP; `pet.yaml` 在 server 侧消费并校验 `id`, `rarity`, `elemental`, `attribute`, `growth`, `skill`, `battleAI` 及技能引用. `growth` 用于生成宠物战斗属性; `attribute.get` 和 `attribute.rate` 与异常抗性、暴击、反击字段一起参与敌人生成EXP公式; `skill`保存玩家宠物可配置技能; `battleAI`仅用于敌方PVE单位, 使用完整英文值配置攻击、防御、逃跑相对权重及普通攻击目标规则. `escapeWeight`是敌方基础逃跑动作权重; 三项权重总和为0时服务端直接防御. `targetScope`允许`allOpponents`、`playerCharacters`、`playerPets`、`partyLeader`; `targetSelection`允许`random`、`highestHp`、`lowestHp`、`highestAttack`、`highestAgility`、`lowestAgility`、`elementalSubdue`. `pet.skill.yaml`提供宠物技能槽引用校验; GuardBreak技能使用空对象`guardBreak: {}`标记8.5第一种破除防御处理器, 当前`9000004`复用攻击目标参数且没有客户端可覆盖的数值; GuardBreak2技能使用空对象`guardBreak2: {}`标记8.5第二种破除防御处理器, 当前`9000011`精确映射旧配置543号技能, Guard目标固定先乘1.3再执行普通Guard减伤, 非Guard目标固定乘0.7, 两个倍率都不能由配置或客户端覆盖; NoGuard技能使用`noGuard.dodgePercent/counterPercent/criticalPercent`, 三项必填, 避%限制在uint16范围, 击%和心%限制在uint8范围. 避%和击%由服务端战斗逻辑读取, 心%只保留8.5原始配置且当前不参与暴击. ContinuationAttack技能使用`continuationAttack.segmentCount`, 段数必填且限制在1至10; 当前`9000005/9000006`分别配置2/3段. AttackShoot技能使用`attackShoot.minSegmentCount/maxSegmentCount`, 两项必填且限制在1至60, 最大值不得小于最小值; 当前`9000013/9000046/9000213/9000214/9000215`分别精确配置8.5技能614号“栗子连激”的8至10段、647号“栗子连激改”的6至8段、1090号“栗子连激-改”的固定10段、1091号“栗子连激-改2”的固定30段和1092号“栗子连激-改3”的固定60段. 固定段数范围仍先消费一次段数RAND; 只有忠诚100才继续执行1/300及条件性低HP 1/50强制8段判定. 目标预抽、C float伤害分摊、每段正伤害20%睡眠和双方禁止反击都是处理器固定规则, 不由客户端覆盖. TearDamage技能使用`tearDamage.missingHpPercent`, 必填且限制在1至450; 当前`9000014/9000015/9000053/9000054/9000055/9000178/9000196/9000203/9000204/9000216/9000217`精确配置8.5技能615/616/655/656/657/1056/1073/1080/1081/1093/1094号“撕裂伤口1/2/3/4/5、撕夜及撕裂伤口6/7/8/9/10”的20%/50%/70%/120%/150%/100%/200%/260%/350%/400%/450%. 90%攻击、80%防御、C float目标缺失HP追加、目标满HP时整次伤害归零、DODGE跳过追加以及不参加合击和反击都是处理器固定规则. MagicStatusChange技能使用`magicStatusChange.status/remainingActions/defensePercent/targetScope`, 当前`9000056`精确配置8.5技能658号“玄武铁壁”的`super_wall/3/50/whole_allied_camp`; 每次物理受击再增加0至19个百分点、己方整营扩展、组内已有状态不刷新和行动开始递减属于共同处理器规则. SetMagicPet技能使用`setMagicPet.effect/remainingActions/power/targetScope`; 当前`9000058/9000059/9000060/9000061`分别保存660卡沃之甲`defense/4/70/whole_allied_camp`、661 T水灵滋润`hp_recovery/3/800/single_allied`、662卡沃之怒`attack/4/70/whole_allied_camp`和663 T风之吹息`agility/4/40/whole_allied_camp`. 攻防敏效果只允许1至100, HP回复还校验110%随机上限不超过C int; 四者共享四属性槽互斥和目标处理器, 客户端不能覆盖配置. 同一个宠物技能最多只能配置一个结构化战斗处理器, 不能同时配置GuardBreak、GuardBreak2、NoGuard、ContinuationAttack、WildViolentAttack、AttackCrazed、AttackShoot、TearDamage、Sars、ColumnAttack、Gyrate、Hector、Retrace、Acupuncture、DamageToHPSecond、FireKill、BecomeFox、ShowMercy、MagicStatusChange、SetMagicPet、Combined、BatFly、DivideAttack和BattleModel. 玩家宠物只有在`pet.yaml skill`实际配置对应技能ID时才能提交这些特殊技能; 当前不在本文件或`pet.yaml`自动分配技能. `exp.yaml`用于角色经验推导等级和敌方等级换算. `offset.yaml` 由资源提取 skill 自动累计生成, 使用顶层 `frameid: [offsetX,offsetY]` 映射且 `frameid` 不可重复; 当前作为共享资源元数据, 不由 server 业务逻辑消费. 角色和宠物的名称、描述、颜色、栖息地、出生地、PNG、`.tpsheet`和frame资源完整性, 以及 `pet.sprite.yaml` 的动画引用和帧表完整性继续由sa.desktop校验.

BecomeFox和ShowMercy也属于上段的结构化战斗处理器互斥集合, 不能和GuardBreak至FireKill或彼此同时配置.

FieldAttributeChange同样属于结构化战斗处理器互斥集合. 一个技能配置该节点后, 不能再同时配置上段列出的任一处理器; 配置入口必须优先报告多处理器歧义, 再报告该节点自己的参数错误.

`pet.skill.yaml`不再保留8.5旧表的通用`option`文本. 每个现代技能通过非空功能节点选择一个服务端处理器, 并在该节点下保存该处理器需要的明确参数. 多个技能ID可以复用同一处理器, 仅名称、说明和参数不同; 客户端动作请求只提交技能ID及目标等行为输入, 不携带技能配置参数. 每个处理器参数结构由自己的`check() error`校验字段完整性和范围, 配置入口在对应功能节点出现时立即调用, 再统一附加技能ID上下文; 同一技能配置多个处理器的歧义错误保持最高优先级. 8.5原始`option`仍保留在`docs/战斗.proto`审计目录中, 只用于核对旧源码解析规则.
